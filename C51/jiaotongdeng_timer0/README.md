# T0 定时交通灯与 INT0 应急控制

按本次实验说明新建，保留原有 `jiaotongdeng`、`jiaotongdeng_int0` 工程。沿用现有的 `main.c + STARTUP.A51 + .uvproj + Objects/ + Listings/` 结构。

## 编译和接线

用 Keil µVision 打开 `jiaotongdeng_timer0.uvproj`，按 F7 编译。芯片 **AT89S51**，晶振 **12 MHz，标准 12T**，HEX 输出为 `Objects/jiaotongdeng_timer0.hex`。

| 引脚 | 功能 |
|---|---|
| P1.0 | 南北绿灯 |
| P1.1 | 南北黄灯 |
| P1.2 | 南北红灯 |
| P1.3 | 东西绿灯 |
| P1.4 | 东西黄灯 |
| P1.5 | 东西红灯 |
| P3.2 / INT0 | K1，松开为高电平，按下接地 |

交通灯沿用现有电路的低电平点亮接法：VCC → 限流电阻 → LED → P1。P1.6、P1.7 保持高电平。MCU 的供电、复位、晶振、EA 接线沿用现有最小系统。

## 程序行为

| 状态 | 南北 | 东西 | P1 |
|---|---|---|---|
| 1 | 绿 | 红 | 0xDE |
| 2 | 黄 | 红 | 0xDD |
| 3 | 红 | 绿 | 0xF3 |
| 4 | 红 | 黄 | 0xEB |
| 应急 | 红 | 红 | 0xDB |

- 每种正常状态持续 N 秒，四种状态循环。按要求默认 **N = 1**，一个正常循环共4秒；修改 `main.c` 顶部的 `PHASE_SECONDS`，允许 1～255。
- T0 工作在定时方式1。12 MHz / 12 = 1 MHz，每次计数 1 µs；50 ms 初值为 `65536 - 50000 = 0x3CB0`，累计20次溢出形成1秒时基。
- K1 的下降沿产生 INT0。中断立即将 P1 输出为 0xDB，暂停 T0，并记录应急请求。
- T1 工作在定时方式1，初值 `65536 - 10000 = 0xD8F0`，累计200次溢出为2秒。期间双向红灯**持续点亮**。
- 2秒后恢复原来的灯光状态，继续该状态的剩余时间；T0 寄存器、50 ms 分频计数和已累计秒数均保留。
- 首次下降沿即响应；应急期间禁止再次触发。应急结束后，按键松开且连续采样为高至少20 ms才重新使能 INT0。长按只响应一次。
- 中断只完成定时记账、事件记录和必要的即时红灯输出；状态切换由主循环处理。

方式1通过中断软件重装初值，实际周期包含少量中断响应与重装开销，以上为标称时间。用于实验计时；实测精度还受晶振影响。

## 使用与核对

1. 上电应显示南北绿、东西红；默认每1秒依次切换四个状态。
2. 在任意状态中途按 K1，两个方向红灯常亮约2秒，再回到被打断的状态。
3. 长按、松开后再按，分别检查单次响应和重新触发。

本次交付为程序工程，不含新绘制的 Proteus 原理图。现有 `fangzhen` 工程的 HEX 路径仍指向原程序；使用新程序时，应另存电路并将 MCU 的 Program File 指向本目录 HEX，再核对 K1 接线。

芯片引脚和定时器资料：[Microchip AT89S51 数据手册](https://ww1.microchip.com/downloads/en/DeviceDoc/doc2487.pdf)。
