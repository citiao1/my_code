# 双电机同步回零与按键相对转 30 度

## 程序结构

当前版本把电机串口、DMA 数据处理和状态机封装在 `EMM_Run()` 内，主循环只保留四个周期处理函数：

```c
key_pro();
bluetooth_pro();
EMM_Run();
oled_pro();
```

需要设置绝对角度时直接调用：

```c
EMM_SetAngle(90.0f, 120.0f);
```

这表示电机 1 转到 90 度、电机 2 转到 120 度。详细接口见 `EASY_MOTOR_API.md`。

- `Src/gpio.c`：`key_scanf()` 使用一个静态变量完成三状态消抖，代码在
  `USER CODE BEGIN/END` 内。
- `Src/key_app.c`：`key_pro()` 每 10 ms 调用一次按键扫描，按下一次就增加
  `key_count` 并调用 `motor_add_30()`。
- `Src/motor_app.c`：提供 `EMM_Init()`、`EMM_Run()`、`EMM_SetAngle()`，内部完成上电使能、双机回零、累计相对运动、位置轮询和外力回正状态机。
- `Src/motor_uart.c`：由 `motor_app.c` 内部使用的 UART4 Receive-to-IDLE DMA 接收。HAL 回调只复制
  数据、置标志并重启 DMA，`motor_uart_process_internal()` 在主循环提取 8 字节位置帧。
- `Src/bluetooth_app.c`：USART2 蓝牙协议。单字节中断接收，在主循环解析
  两台电机的目标角度命令，转换为角度后调用 `EMM_SetAngle()`，并每秒返回实际角度、目标角度和状态。
- `Src/oled_app.c`：只有一个 `oled_pro()`，每 200 ms 直接使用 `sprintf()` 和
  OLED 库函数刷新屏幕。
- `Src/oled.c`、`Src/font.c`：采用 `stm32_hal_ssd1306` 的显存、字体和绘图逻辑，底层使用 PD11-PD14 软件 SPI。
- `Src/Emm_V5.c`：厂商电机协议，保持原有命令接口。

主循环不会因为位置超时进入永久故障状态。位置接收异常只增加 OLED 上的
`ERR`，随后继续查询；按键控制不会因此被锁死。

## 实际动作

1. 上电等待 500 ms，依次使能地址 `1`、`2`。
2. 依次向地址 `1`、`2` 发送单圈就近回零命令。
3. 等待 3 秒后开始检测 PE0 用户按键。
4. 每次稳定按下 PE0，分别给地址 `1`、`2` 装载 267 脉冲命令。
5. 两条命令都使用 `raF=0`，即相对上一次输入目标继续顺时针增加 30 度。
6. 最后向广播地址 `0` 发送同步启动命令。

所以连续按键的目标是 30、60、90 度，而不是重复回到绝对 30 度。
保持状态下会轮流读取两台电机的位置；连续 3 组采样超过 1.5 度容差时，
使用 `raF=1` 返回已保存的累计目标。回正命令不会改变下一次按键的累计关系。
上位机可以给两台电机设置不同的绝对目标，程序先分别装载两条命令，再用
广播地址 `0` 同步启动。此后按键仍是在两台电机各自目标上继续增加 30 度。

## OLED 接线与显示

| OLED 信号 | F407 引脚 |
| --- | --- |
| DC | PD11 |
| RST | PD12 |
| DATA | PD13 |
| CLK | PD14 |
| VCC | 3.3 V |
| GND | GND |

屏幕内容：

- `M1`、`M2`：两台电机的实时位置；后面的 `V` 表示是否收到过有效位置帧。
- `KEY`：检测到的按键次数。
- `CMD`：已经下发的双电机同步运动次数，包括按键和上位机命令。
- `T1`、`T2`：两台电机各自的目标角度。
- `ST`：电机状态机当前状态。
- `RXE`：DMA、帧解析和位置查询超时的累计次数。
- `COR`：检测到外力偏移后自动回正的次数。
- `PEND`：尚未执行的按键运动次数。
- `BT`、`LAST`：蓝牙累计收到的字节数和最后一个字节的十六进制值。

## 电机串口接收

电机使用 `UART4`，波特率为 115200，格式为 8N1。`EMM_Init()` 内部启动：

```c
HAL_UARTEx_ReceiveToIdle_DMA(&huart4, dma_rx_data, 32);
```

串口空闲或缓冲区收满时，HAL 调用 `HAL_UARTEx_RxEventCallback()`。回调只把
本次数据复制到接收数组、置 `rx_flag`，然后立即重新启动 DMA。主循环中的
`EMM_Run()` 内部看到标志后提取 `S_CPOS` 的 8 字节位置回复；普通命令的 4 字节
应答不参与控制，直接忽略。这样中断函数短，协议解析也集中在一个独立文件中。

UART4 的 DMA 分配如下：

| 方向 | DMA |
| --- | --- |
| UART4_RX | DMA1 Stream2 Channel4 |
| UART4_TX | DMA1 Stream4 Channel4 |

## 蓝牙控制协议

蓝牙使用 `USART2`，波特率为 9600，格式为 8N1，不占用 DMA。程序启动后发送：

```text
BT READY
```

上位机发送如下命令，角度单位为 0.1 度：

```text
SET,300,600
```

表示电机 1 转到 +30.0 度，电机 2 转到 +60.0 度。正数为顺时针，负数为
逆时针，范围为 -360.0 到 +360.0 度。单片机接受后回复：

```text
OK,SET,300,600
```

此后每秒返回一次：

```text
STAT,300,600,300,600,5
```

五个数字依次为两台电机实际角度、两台电机目标角度和状态机编号，前四项
单位均为 0.1 度。蓝牙接收方式与 `diansai_test` 相同：
`HAL_UART_Receive_IT()` 每次接收 1 字节，`HAL_UART_RxCpltCallback()` 保存字节后
立即启动下一次接收。命令解析仍位于主循环调用的 `bluetooth_pro()`。

## 网页上位机

先完全关闭旧的 `BT04_Motor_Control.exe`，然后双击
`WebUpperComputer/start_web.bat`。脚本会启动本地网页服务器并打开
`http://127.0.0.1:8000`。请使用最新版 Edge 或 Chrome，不能直接双击
`index.html`。

点击“连接设备”并在浏览器列表中选择任意名称的 BLE 串口模块。模块需要提供
`FFE0` 服务；网页与 `diansai_test/vehicle-console` 一样，
优先选择可写的 `FFE1`，否则使用 `FFE2`，并优先带响应写入；`FFE1` 用于接收
通知。可以分别输入电机 1、电机 2 的绝对目标角度并同步发送，也可以让
两台目标同时增加 30 度或回到 0 度。界面持续显示实际角度、目标角度、状态
和通信日志。详细说明见 `WebUpperComputer/README.md`。

烧录最新 `MDK-ARM/F407_Emm_Normal.hex` 后，发送一次命令时先观察 OLED：

- `BT` 增加：USART2 已经收到蓝牙字节。
- `BT` 增加而 `CMD` 不增加：继续检查命令换行和解析。
- 收到 `OK,SET` 而电机不动：继续检查电机状态机和 UART4 总线。

正常的网页目标命令状态路径是 `05 -> 12 -> 13 -> 08`，运动完成后回到 `05`。

## 接线

### 两台电机共用 UART4

| F407 | 电机总线 |
| --- | --- |
| PC10 / UART4_TX | 两台电机 TTL_RX |
| PC11 / UART4_RX | 两台电机 TTL_TX |
| GND | 两台电机 GND |
| PE0 | 板载用户按键 |

电机单独供电并与开发板共地。连接 PC11 前确认电机 TTL_TX 为 3.3 V。
两台电机必须分别设置地址 `1` 和 `2`，并关闭主动周期上报，避免两个地址
同时向同一根 RX 线发送数据。

### 蓝牙使用 USART2

| F407 | 蓝牙模块 |
| --- | --- |
| PD5 / USART2_TX | RXD |
| PD6 / USART2_RX | TXD |
| GND | GND |

串口线要交叉连接，即开发板 TX 接模块 RXD，开发板 RX 接模块 TXD。若使用
开发板原有的板载蓝牙插座，保持插座原接法即可，不要再把电机接到 PD5/PD6。
蓝牙模块供电按模块标注选择；送入 PD6 的 TXD 电平必须是 3.3 V，不能直接
输入 5 V TTL。

## 零点校准

正常运行时，`Src/motor_app.c` 顶部的：

```c
#define CALIBRATE_MOTOR_1_ON_BOOT  0
#define CALIBRATE_MOTOR_2_ON_BOOT  0
```

必须保持为 `0`。需要重新保存某台电机零点时，把机构手动放到真实零点，
只将对应宏临时改为 `1`，编译烧录并上电一次；随后立即恢复为 `0`，重新
编译烧录正常固件。不要长期保持为 `1`。
