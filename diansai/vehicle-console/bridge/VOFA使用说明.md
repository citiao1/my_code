# BLE 桥接与 VOFA+ 使用说明

## 启动

在 `D:\my_code\my_code\diansai` 打开 PowerShell，运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\vehicle-console\bridge\start-bridge.ps1
```

第一次运行会创建隔离的 Python 环境并安装 `bleak` 与 `websockets`，需要等待几十秒。之后会自动：

- 扫描并连接带有 FFE0 服务的 BLE 串口模块。
- 在 `127.0.0.1:1347` 启动 VOFA+ TCP 数据端口。
- 在 `127.0.0.1:8766` 启动网页控制 WebSocket。
- 在 `http://127.0.0.1:8765` 启动网页上位机。

如果扫描到多个 FFE0 设备，输入设备前面的数字并回车。运行期间不要再用网页的“BLE 蓝牙”模式或 `serial.keysking.com` 连接同一个模块。

## 网页控制

打开 `http://127.0.0.1:8765`，连接方式选择“本地桥接”，点击“连接桥接”。

## VOFA+ 配置

1. 打开 VOFA+ 并新建工程。
2. 数据引擎选择 `TCPClient`。
3. 远端地址填写 `127.0.0.1`。
4. 远端端口填写 `1347`。
5. 协议引擎选择 `FireWater`。
6. 点击连接。

FireWater 的格式是一个可选前缀加一组纯数字：

```text
vehicle:ch0,ch1,ch2,...,ch22\n
```

冒号后不能再写 `speedL:` 之类的字段名，否则只会成功解析第一个通道。桥接程序只向 VOFA 输出调参需要的 23 个快速通道，固定对应关系如下：

```text
ch0  time_ms              ch1  motor_enable
ch2  link                 ch3  yaw_deg
ch4  speed_left           ch5  speed_right
ch6  target_left          ch7  target_right
ch8  pwm_left             ch9  pwm_right
ch10 target_yaw_rate      ch11 yaw_rate
ch12 yaw_rate_error       ch13 yaw_correction_m_s
ch14 yaw_loop_enabled     ch15 mpu_ok
ch16 yaw_feedforward_m_s  ch17 target_heading_deg
ch18 heading_error_deg    ch19 heading_output_deg_s
ch20 heading_enabled      ch21 heading_hold_active
ch22 battery_voltage_v
```

速度、目标和误差的单位都是 `m/s`。在波形控件中添加 `ch6`、`ch7`、`ch8`、`ch9`，即可同时观察左右轮实际速度与目标速度。

不要把 `ch0` 加入速度波形。它是从上电开始累计的毫秒计时值，数值会越来越大，只用于检查数据包时间。

当前霍尔编码器实测标定值：左轮 `1558.3 count/rev、7514 count/m`，右轮 `1557.4 count/rev、7263 count/m`。物理左轮对应 TIM3，物理右轮对应 TIM2，固件已经交换为正确的左右显示。

左右速度环采用独立增量式 PID：`deltaPWM = Kp*(e-e1) + Ki*e + Kd*(e-2e1+e2)`，再通过 `PWM += deltaPWM` 累加输出。停车、断链或修改参数时会清空累计输出。

## 速度环初次调参

1. 先把车架空，确保两个轮子离地。
2. 固件和网页默认使用最高轮速 `200 mm/s`、左右轮 `Kp=4000, Ki=800, Kd=0`；连接后先点击一次“应用参数”。
3. 短按前进，确认 `ch8/ch9` 和 `ch6/ch7` 的正负号一致。若目标为正而实际速度为负，立即急停，不要继续加参数。
4. 逐步增加 Kp，直到响应足够快但不持续振荡。
5. 再从较小的 Ki 开始增加，用于消除稳态误差。速度环通常先保持 `Kd=0`。

## 角速度环初次调试

1. 角速度环在 MPU6050 初始化成功后默认开启，默认参数为 `Kp=0.001, Ki=0.002, Kd=0, Kff=0.001205`，最大角速度 `150deg/s`。若MPU初始化失败，固件保持闭环关闭并在停车时自动重试。
2. 首次改线或更换电机后可暂时取消网页“启用”，按住左转确认 `ch10` 与 `ch11` 同号；右转时两者也应同号，确认后重新启用。
3. 波形同时观察 `ch10`、`ch11`、`ch12`、`ch13`。先增加 Kp，角速度能跟随但不持续振荡后，再考虑少量 Ki。
4. 若实际角速度与目标反号或启用后车辆突然满差速，立即急停并关闭角速度环。
5. `ch15` 为 MPU6050 状态：`1` 正常，`0` 表示初始化失败或连续读取失败，固件会在停车时自动重试。
6. 前馈调试时用稳定转弯数据估算 `Kff = abs(ch13) / abs(ch10)`，先填估算值的 80%。`ch16` 显示前馈实际贡献，单位为 `m/s`。

## 航向方向外环初次调试

1. 方向环参考 LQ 使用陀螺仪角速度作为阻尼的思路，当前用 MPU6050 航向替代赛道偏差。外环每 `30ms` 生成限速航向轨迹，输出由 `Kff * 轨迹角速度 + Kp * 轨迹跟踪误差 + Kd * (轨迹角速度 - 实际角速度)` 组成，避免直接差分航向误差导致 `ch19` 噪声尖峰。
2. 方向环在 MPU6050 初始化成功后也默认开启，参数为 `Kp=4.0, Kd=0.3, Kff=1.0, 最大输出=80deg/s`。固件自动捕获当前航向，手动左右转向期间方向环暂停，松开后捕获新航向。
3. 调试时让车辆保持前进，点击采集当前航向，将测试目标增加 `10~20deg` 后发送。观察 `ch17`、`ch3`、`ch18`、`ch19`。
4. `Kff=0` 可关闭新前馈以作对照；从 `0.6` 开始增加，响应仍慢就逐步提高到 `1.0`。若 `ch19` 已到限幅而 `ch11` 跟不上，瓶颈在角速度环、电机或轮速饱和，继续增加方向环前馈无效。
5. 网页的自动测试会自动启用两层闭环，以设定油门直行，依次执行 `+航向阶跃 -> 基准 -> -航向阶跃 -> 基准`，完成后自动停车。默认使用 `20%` 油门、`10deg` 阶跃、每段 `2.5s`。
6. `左转4x90deg` 和 `右转4x90deg` 会以零油门原地差速，依次到达四个相隔 `90deg` 的绝对航向。每段要求角度误差不超过 `1deg`、角速度不超过 `4deg/s` 并连续稳定 `400ms`，最后回到起始航向并自动停车。
7. 目标轨迹到位后，若剩余误差大于 `0.5deg` 且角速度低于 `5deg/s`，固件会提供最小 `8deg/s` 的快速修正；进入 `0.5deg` 后自动退出，避免在目标附近持续抖动。
8. 自动测试期间窗口失焦、断开连接、点击急停或使用手动方向键都会立即发送 `STOP` 并终止测试；任一 `90deg` 阶段超过 `7s` 也会自动停车。

## 1米正方形自动测试

1. 网页可选择左转或右转正方形，固件依次执行 `前进1m -> 原地转90deg`，循环四次后回到起始航向并停车。
2. 左轮使用 `7514 count/m`，右轮使用 `7263 count/m`。每条边分别换算左右轮距离后取平均值，不直接把两个编码器原始计数混用。
3. 直线段采用位置比例降速，距离目标允许误差为 `+-10mm`；接近1米时会降低目标速度，过冲超过1cm时允许短距离倒退修正。
4. 每条边距离、航向和速度连续稳定 `400ms` 后才转向。直行单边超过 `30s` 或单次转向超过 `10s` 会进入异常停止。
5. 网页的直行油门只限定最大速度，建议先用 `30%`。测试期间网页每 `100ms` 发送一次 `PING`，通信中断超过 `400ms` 时固件立即停车。

## 电池 ADC

电池采样使用 `PB0 / ADC1_IN8`。原理图分压为 VIN 经 `100k` 到 PB0、PB0 经 `10k` 到地，固件按 `11:1` 换算。VOFA 的 `ch22` 是估算电池电压，ADC 原始值只在网页低速状态数据中显示。首次使用需用万用表对比校准，不启用自动欠压停车。

## 常见问题

- `no FFE0 device found`：确认蓝牙模块已供电，并关闭其他正在连接该模块的网页或应用。
- 网页显示桥接未运行：先保持桥接 PowerShell 窗口开启，再刷新网页。
- VOFA+ 连接不上：确认数据引擎是 TCPClient，不是 SerialPort，并检查端口是否为 1347。
- 关闭桥接：在桥接 PowerShell 窗口按 `Ctrl+C`，固件会在 400ms 内因命令超时停车。
