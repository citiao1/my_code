# MSPM0G3507 智能车完整说明书

适用工程：`MSPM0G3507_Diansai_Test`  
固件协议版本：V24  
文档日期：2026-07-18

本文是当前实车、固件、网页上位机和 WHEELTEC-IOS 蓝牙桥的统一说明。文中“已锁定”表示参数已经过实车验证，正常使用时不应继续修改；“待标定”表示必须以本车实测数据为准，不能直接照抄参考工程。

## 1. 当前可用基线

当前工程已经实现并构建通过以下功能：

- 双 AT8236 电机 20 kHz 慢衰减驱动，原始 PWM 独立测试范围为 `-100..100%`。
- 左右编码器累计计数、实际周期测速和一阶低通滤波；两侧均使用 `1867 count/m`。
- 左右轮独立增量式速度 PI，锁定参数均为 `4000/800/0`。
- LSM6DSR 角速度、相对航向角和静止偏置校准。
- 位置式角速度 PID，当前参数 `1000/2000/0/1205`，最大遥控角速度 `150 deg/s`。
- 遥控直行航向环，锁定参数 `Kp=4.000、Kd=0.300、Kff=1.000`，参考角速度上限 `80 deg/s`。
- 八路灰度采样、逐通道双色标定、归一化、寻线方向 PID 和直角弯丢线恢复状态机。
- 黑底/白底模式切换、本地按键标定、长按发车、蜂鸣器反馈和电池电压显示。
- 网页方向键及 `W/A/S/D` 遥控、PID 面板、自动航向阶跃、正方形测试、死区测量和 VOFA+ 转发。
- UART0 发送 DMA、接收 FIFO 轮询、500 ms 电机命令看门狗和蓝牙自动重连。

当前关键默认值如下。

| 灰度方向环周期 | 20 ms | 固定 |

## 2. 第一次上电前检查

1. 拔掉电池中转线，检查电机、电机驱动、编码器、灰度、IMU、蓝牙和主板是否共地。
2. 按原理图和下表核对每一根线；重点检查电池正负、AT8236 的 `VM` 与逻辑电源，禁止用 MCU 3.3 V 给电机供电。
3. 在完全断电并拔出电池后，用万用表蜂鸣档检查电源正负之间是否意外短路。
4. 将车辆架空，确保四周无人、轮胎不会接触桌面或线缆。
5. 先只给逻辑系统上电，观察是否出现 IMU 成功的两声短响；三声长响表示 IMU 初始化或标定失败。
6. 连接上位机后先执行 `HELP`、`ENCZERO`，确认命令下行与遥测上行均正常。
7. 只在以上步骤通过后，用独立电机测试从小 PWM 开始确认左右轮方向、编码器正负和急停。
8. 落地前把速度设到最低，准备随时点击网页中央停止键或断开电机电源。

## 3. 硬件连接

所有数字信号均为 3.3 V 逻辑，所有模块必须与 MSPM0G3507 共地。

| 设备信号 | MSPM0G3507 引脚 | 说明 |
| --- | --- | --- |
| WHEELTEC RXD | PA10 / UART0 TX | 9600 8N1 |
| WHEELTEC TXD | PA11 / UART0 RX | 9600 8N1 |
| AT8236 AIN1/AIN2 | PB2 / PB3 | TIMA1 CH0/CH1 PWM，左轮 |
| AT8236 BIN1/BIN2 | PB10 / PB11 | TIMG0 CH0/CH1 PWM，右轮 |
| 左编码器 A/B | PA7 / PA3 | A 计数，B 判向 |
| 右编码器 A/B | PA8 / PB7 | A 计数，B 判向 |
| 灰度 OUT | PA27 | 12 位 ADC |
| 灰度 S0/S1/S2 | PA26/PA25/PA24 | 八选一模拟多路复用 |
| OLED | PA17/PA16/PB21/PB23/PB22 | 库仍保留，应用已禁用刷新 |
| 9AGM SPI | PA12/PA13/PA14/PA2 | SCK、数据对、CS；数据方向开机自动探测 |
| K1/K2/K3 | PB15/PB14/PB16 | 低电平按下，顺序已在实板验证 |
| 蜂鸣器 | PA28 | 三极管驱动，有源蜂鸣器 |
| SW1/SW2 | PB6/PB8 | 低电平为拨下，2.2 kOhm 上拉 |

## 5. 在另一台 Windows 电脑部署上位机

### 5.1 前提

- Windows 10 或 Windows 11。
- 可用的蓝牙适配器和已供电、未被手机占用的 `WHEELTEC-IOS`。
- Chrome 或 Edge。
- Python 3；首次安装 Python 依赖时需要网络。
- 完整复制本工程目录，不能只复制 `index.html`。

### 5.2 启动

在工程根目录打开 PowerShell：

```powershell
powershell -ExecutionPolicy Bypass -File .\host-console\bridge\start-wheeltec.ps1
```

脚本会完成以下工作：

1. 优先寻找 Codex 随附 Python，否则使用系统 `python`。
2. 若不存在可用 `.venv`，创建新的虚拟环境。
3. 安装 `bleak` 与 `websockets`。
4. 启动本地网页服务器、WebSocket 桥和 VOFA TCP 服务。
5. 扫描并连接名称为 `WHEELTEC-IOS` 的 BLE 设备。

保持 PowerShell 窗口打开，在浏览器访问：

```text
http://127.0.0.1:8770
```

网页选择“WHEELTEC 本地桥接”并点击“连接桥接”。正常日志必须识别 `FFE1 notify` 与 `FFE2 write`。三个本地端口为：

| 服务 | 地址 |
| --- | --- |
| 网页 | `http://127.0.0.1:8770` |
| 浏览器 WebSocket | `ws://127.0.0.1:8766` |
| VOFA+ TCP | `127.0.0.1:1347` |

正常退出时在 PowerShell 中按 `Ctrl+C`。只关闭网页会触发安全停止，但桥接进程仍在运行。

### 5.3 异机常见问题

- 仓库中的 `.venv` 可能记录原电脑的 Python 路径。若启动时报解释器路径无效，删除 `host-console/bridge/.venv` 后重新运行脚本。
- 端口 8766 被占用时，脚本会拒绝启动。先关闭旧桥，不要同时运行两份。
- 扫描不到设备时，确认模块供电、手机未连接该模块，然后给蓝牙模块重新上电。
- Windows 偶尔只返回部分 GATT 表。桥接会拒绝只有 FFE1、没有 FFE2 的“只收不发”连接并自动重试。
- 可用网页的“直接串口”模式进行有线排障，串口参数仍为 9600 8N1。

## 6. 网页上位机使用

### 6.1 遥控与 WASD

方向按钮和键盘共用同一条 `DRV,throttle,steering` 安全路径：

- `W` 前进，`S` 后退，`A` 左转，`D` 右转。
- 支持 `W+A`、`W+D`、`S+A`、`S+D` 组合。
- 松开最后一个方向键会停车。
- 输入框、滑块或下拉框获得焦点时，不接管 WASD，避免输入参数时误动车辆。
- 浏览器失焦、页面隐藏、连接断开都会发送停止。
- 中央方形停止按钮是网页急停。

“目标速度比例”按最大 600 mm/s 换算。例如 10% 为 60 mm/s，60% 为 360 mm/s。遥控直行时自动捕获当前航向并启用锁定航向环；按下 A/D 时改为直接给角速度环目标，松开转向且仍有前进/后退命令时重新捕获当前航向。

### 6.2 速度环面板

左右速度参数显示为 `4000/800/0` 且只读。固件仍识别旧的 `PID/PIDL/PIDR` 命令，但会返回 `ERR,SPEED_PID_LOCKED`，防止误操作破坏已经验证的参数。目标速度和实际速度可在网页遥测或 VOFA `I15/I16、I18/I19` 查看。

### 6.3 角速度环面板

可设置启用状态、最大角速度以及 `Kp/Ki/Kd/Kff`。网页显示的是与参考工程一致的微单位整数，例如 `1000/2000/0/1205`。点击“应用角速度参数”后，网页会先标记“等待确认”，只有固件遥测回读同一组参数后才结束等待；编辑中的表单不会再被旧遥测覆盖。

角速度目标、实际和误差分别看 VOFA `I34/I35/I36`。正值表示左转，负值表示右转。

### 6.4 遥控方向环与自动阶跃

遥控航向参数已锁定为 `4.000/0.300/1.000、80 deg/s`。日常遥控无需手动开启，直行时固件自动采用它。自动测试会围绕当前基准航向交替产生正负阶跃，并根据角度误差、角速度、稳定时间和单步超时判断是否进入下一步。测试中页面失焦、隐藏或断连都会停止。

航向曲线建议同时观察：

- `I4 + I6`：最终目标航向与实际航向。
- `I5 + I6`：限速参考航向与实际航向。
- `I9 + I10`：方向环给出的目标角速度与实际角速度。

### 6.5 寻线方向环

面板可设置方向 `Kp/Ki/Kd`、最大差速比例和基础速度。网页显示浮点数，发送时乘 1000，例如 `200.000/0.000/350.000` 会发送 `LINEPID,200000,0,350000`，差速 `0.650` 会发送 `LINEDIFF,650`。

点击开始后，网页每 200 ms 续发 `LINE,1,speed`。标定无效、IMU 不正常或角速度环关闭时固件会拒绝启动。寻线模式使用独立灰度方向环，不使用遥控航向环；两种方向环不会同时接管目标角速度。

### 6.6 灰度显示与两种赛道模式

八路通道同时显示原始 ADC `0..4095` 与归一化 `0..1000`。归一化固定解释为“背景=0、目标线=1000”，因此方向算法不需要知道颜色本身。

| SW1 | 模式 | K1 标定 | K2 标定 | 车辆跟随 |
| --- | --- | --- | --- | --- |
| 拨下，PB6=低 | 白底黑线 | 白色背景 | 黑色目标线 | 黑线 |
| 拨上，PB6=高 | 蓝底白线 | 蓝色背景 | 白色目标线 | 白线 |

实测蓝色 ADC 大、白色 ADC 小。在蓝底白线模式中分母为负数是正确现象，不能使用无符号除法。SW1 每次切换都会停车并清除旧颜色标定，必须重新采集。标定只保存在 RAM，断电后也必须重做。

### 6.7 正方形测试

点击“正方形测试”后，浏览器只发送一次 `SQUARE,1`，随后每 200 ms 发送 `SQUARE,2` 续命。固件执行：直走 1 m、稳定、左转 90 度、稳定，重复四次。网页显示边号、阶段、已走距离、剩余距离和目标航向。任一阶段超时、失去续命或点击停止都会停车。

此测试必须在编码器、速度环、角速度环和遥控航向环均已确认后进行。首次测试应在空旷区域，并有人准备断电。

### 6.8 独立电机与死区工具

独立电机滑块发送原始 `MOTOR,left,right`，绕过速度 PID 与死区映射。死区工具一次只测试一个电机的一个方向：

1. 架空确认方向和急停，随后落地并使用实际机械负载。
2. 从 0 开始每次增加 1%，直到可靠启动，记录“启动值”。
3. 不停车，逐步减小 PWM，直到刚好还能持续转动，记录“运行值”。
4. 左正、左反、右正、右反分别测量；可同时记录负载下电池电压。

当前慢衰减实测为左正 8/8%，其余三个方向 7/7%。启动值与运行值相同，因此没有必要增加启动冲击。死区映射代码仍保留，但当前 `SPEED_FEEDFORWARD_ENABLED=0`，调好的速度 PI 独立承担输出。

### 6.9 电池电压

网页电池电压来自 PB19 分压估算，只用于监视，当前没有自动欠压切断。首次使用必须在车辆带载时用万用表同时测量电池端电压，比较显示误差。未完成实板修正前，不能把网页数字直接作为过放保护阈值。

## 7. 板载按键、拨码和蜂鸣器

### 7.1 按键

| 按键 | 实际引脚 | 短按 | 长按/运行中按下 |
| --- | --- | --- | --- |
| K1 | PB15 | 采集当前模式的背景 | 标定有效时按住 500 ms 本地发车；运行中按下停车 |
| K2 | PB14 | 采集当前模式的目标线 | 标定有效时按住 500 ms 本地发车；运行中按下停车 |
| K3 | PB16 | 停车并重新标定陀螺仪 | 长按作为本地急停并三声警告 |

K1/K2 的实板顺序与早期厂家表格相反，代码已经按实板验证结果修正。不要再按旧表交换 PB14/PB15。

本地发车条件是两次颜色采集均有效且八路归一化跨度全部合格。K1 或 K2 按下后蜂鸣器连续鸣响，满 500 ms 后停止蜂鸣并以 200 mm/s 发车。倒计时和本地运行期间，网页的驱动与调参命令不会抢占车辆；真正丢线或再次按 K1/K2 才停车。

### 7.2 蜂鸣器提示

| 声音 | 含义 |
| --- | --- |
| 一声短响 | 一次背景或目标线采集完成 |
| 三声短响 | 两组参考均有效，八路归一化成功 |
| 两声短响 | IMU 启动或重新标定成功 |
| 三声长响 | IMU 或本地启动条件错误 |
| 连续响 500 ms | 本地发车倒计时 |

板上是经 S8050 驱动的有源蜂鸣器。软件可以可靠改变持续时间与节奏，不能可靠改变音调。要演奏不同音高，需要更换为无源蜂鸣器并使用定时器 PWM。

### 7.3 拨码

SW1 选择赛道颜色并在切换时停车、清除标定。SW2 已完成消抖和状态上报，但当前没有绑定车辆动作，留作后续功能开关。

## 8. 软件结构

### 8.1 分层

```text
网页 / VOFA+
      |
Python BLE-WebSocket-TCP 桥
      |
wheeltec_link：UART0 RX 行接收 + TX DMA 队列
      |
vehicle_command：纯命令语法解析
      |
diansai_app：模式、安全权限、目标和 10 ms 调度
      |
line / square / cascade 控制算法
      |
motor / encoder / imu / gray / battery / board_io 硬件模块
```

### 8.2 模块职责

| 模块 | 唯一职责 |
| --- | --- |
| `diansai_app.c/.h` | 10 ms 调度、模式所有权、命令语义、看门狗、安全停车 |
| `vehicle_command.c/.h` | 把一行 ASCII 命令解析为定长类型和参数，不修改车辆状态 |
| `vehicle_telemetry.c/.h` | 从只读快照生成全部兼容遥测帧 |
| `wheeltec_link.c/.h` | UART0 初始化、RX 行组装、TX 软件队列与 DMA 提交 |
| `vehicle_motor.c/.h` | AT8236 慢衰减 PWM、限幅、换向保护 |
| `vehicle_encoder.c/.h` | 编码器读取、累计值、实际周期速度、滤波 |
| `vehicle_imu.c/.h` | SPI 自动探测、LSM6DSR 初始化、偏置、角速度与航向 |
| `vehicle_gray.c/.h` | 八选一 ADC 采样、参考采集、逐通道归一化 |
| `vehicle_battery.c/.h` | PB19 电池 ADC、分压换算与滤波 |
| `board_io.c/.h` | 按键/拨码消抖、事件、非阻塞蜂鸣队列 |
| `vehicle_cascade_control.c/.h` | 航向、角速度、左右轮速度三级串联控制 |
| `vehicle_line_control.c/.h` | 灰度重心、方向 PID、转向记忆、丢线恢复 |
| `vehicle_square_test.c/.h` | 1 m 与 90 度交替的正方形状态机 |

应用层是运行模式、目标值和安全权限的唯一所有者。协议与遥测模块不能保存第二份 PID 或车辆模式，否则会再次出现“网页刚修改，遥测又把参数改回去”的状态竞争。

### 8.3 调度顺序

SysTick 每 1 ms 增加时基。主循环每次都先服务 UART TX DMA 和 RX FIFO，然后只有累计时间达到 10 ms 才执行控制任务：

1. 按键、拨码和蜂鸣器更新。
2. 编码器按真实 `elapsed_ms` 计算速度。
3. 根据电机与编码器判断静止状态，更新 IMU 与在线偏置。
4. 每 20 ms 采集灰度并先计算寻线目标角速度。
5. 每 100 ms 更新电池。
6. 检查 500 ms 电机命令看门狗。
7. 更新正方形状态机和三级串级控制。
8. 按带宽预算发送 SPD/LIN/TEL/STA/DBG。
9. 再次服务 UART TX DMA。

灰度外环必须先于角速度环运行，新的线偏差才能在同一个周期内转成轮速差。

## 9. 串口、DMA 与蓝牙桥

### 9.1 当前 DMA 方案

UART0 发送已经使用 DMA0。`WheeltecLink_SendText()` 只把完整报文写入 1024 字节环形队列；`WheeltecLink_ServiceTx()` 把从队尾到内存末端的一段连续数据交给 DMA。DMA 完成后推进队尾，发生环形回绕时再提交下一段。目标寄存器地址固定，源地址逐字节递增，主循环无需等待 9600 波特率把每个字符发完。

这解决了最主要的性能压力：长遥测报文不会阻塞 10 ms 控制、IMU 积分或看门狗。队列空间不足时整条报文丢弃，不发送半帧破坏协议同步。

### 9.2 为什么 RX 暂不使用 DMA

RX 命令通常只有十几到几十字节，以 `CR/LF` 结束，而且主循环在 10 ms 调度门限之前高频清空硬件 FIFO。9600 baud 理论上约 960 字节/秒，逐字节读取这一负载相对 80 MHz MCU 很小。

把 RX 改为 DMA 并非不能做，但必须同时增加循环 DMA 缓冲、写指针追踪、换行边界、溢出恢复以及空闲线或定时判帧。MSPM0 UART 的短变长文本在当前频率下不会因此获得可测的控制性能收益，反而会扩大丢命令的风险。因此当前选择是：发送 DMA，接收 FIFO 轮询。若以后改成高波特率二进制定长流，再评估 RX DMA。

### 9.3 蓝牙稳定性设计

- 浏览器不直接持有 BLE；Python 桥负责扫描、订阅、写入和重连。
- FFE1 专门通知，FFE2 使用带响应写入；缺失任一特征都不报告已连接。
- 单次 GATT 写失败只触发 BLE 重连，不关闭浏览器 WebSocket。
- 固件降低 9600 波特率持续流量：普通 SPD 300 ms，寻线 SPD 1000 ms，LIN 400 ms，DBG 4000 ms，运行时 TEL/STA 4000 ms。
- VOFA 使用一个固定 66 通道帧，不让不同长度的报文互相覆盖通道编号。

## 10. 控制算法

### 10.1 AT8236 慢衰减

正向输出为 `IN1=1、IN2=PWM`，反向为 `IN1=PWM、IN2=1`；PWM 比较值取补码，使上位机命令仍表示 0..100% 的驱动占空比。零命令把两个输入清零，换向前也先清零两路，避免 H 桥瞬间反向和大电流冲击。

快衰减在 PWM 关闭阶段让绕组电流快速下降，低占空比平均电流与转矩显著降低；慢衰减让电流在桥内回流，下降更慢，低占空比仍能形成有效平均转矩。本车从快衰减约 57% 启动门槛降到慢衰减 7..8%，说明此前主要是驱动调制模式造成的“表观死区”，不是四个电机同时出现了巨大机械死区。

### 10.2 编码器与速度滤波

当前驱动只统计编码器 A 相的一个下降沿，B 相用于判断方向，因此不能直接使用 STM32 四倍频工程的 count/m。

```text
raw_speed_mm_s = delta_count * 1000 * 1000
                 / (counts_per_meter * elapsed_ms)
filtered_speed = 0.65 * previous_filtered + 0.35 * raw_speed
```

`elapsed_ms` 使用实际调度间隔。即使某次任务晚于 10 ms，积累的编码器脉冲也不会被错误地当作 10 ms 内产生。

### 10.3 增量式速度 PI/PID

左右轮各自使用标准增量式：

```text
e[k] = target_speed - measured_speed
du = Kp*(e[k]-e[k-1])
   + Ki*e[k]
   + Kd*(e[k]-2*e[k-1]+e[k-2])
u[k] = clamp(u[k-1] + du, -100%, 100%)
```

参数沿用 `diansai_test` 和龙邱 `PID_INCREMENT` 的逻辑，只在配置入口把 m/s、16799 计数 PWM 换算为本工程的 mm/s、百分比。实际周期偏离 10 ms 时，Ki 按周期比例缩放，Kd 按反比例缩放，比例限制为 0.5..5。目标方向翻转或目标归零时清空历史，避免旧方向累计输出拖慢换向。

当前前馈为零，速度 PID 的反馈和最终输出均允许 `-100..100%`。若以后重新启用死区映射，非零目标才会从各方向的最小 PWM 开始线性映射，零目标必须仍严格输出零。

### 10.4 角速度环

角速度环是标准位置式 PID 加目标前馈，输出是左右轮差速修正 `mm/s`：

```text
e_yaw = target_yaw_rate - measured_yaw_rate
correction = Kff*target_yaw_rate
           + Kp*e_yaw
           + Ki*integral(e_yaw)
           + Kd*d(e_yaw)/dt
left_target  = forward_speed - correction
right_target = forward_speed + correction
```

积分限幅为 `+/-300 degree*s`，普通差速输出限幅为 `+/-600 mm/s`，并使用条件积分抗饱和。当前网页整数 `1000/2000/0/1205` 在内部换算为参考工程同一物理增益。正角速度定义为左转，右转为负；IMU GZ 两条换算路径都乘以 `-1` 来符合车体坐标。

### 10.5 遥控航向环

航向环不是直接输出电机，而是输出角速度目标。它先把目标航向限制成最大 80 deg/s 的斜坡参考，再计算：

```text
tracking_error = wrap(reference_heading - measured_heading)
rate_error = reference_heading_rate - measured_yaw_rate
target_yaw_rate = Kff*reference_heading_rate
                + Kp*tracking_error
                + Kd*rate_error
```

角度误差始终折算到 `-180..180 deg` 的最短路径。参考已经到达终点、实际误差仍超过 0.5 deg、车体角速度小于 5 deg/s 且控制输出过小时，会给至少 8 deg/s 的校正，克服静摩擦附近的停滞。航向环每 30 ms 更新，角速度环和速度环仍按 10 ms 更新。

### 10.6 灰度归一化

每路切换 S0/S1/S2 后等待 5 us，丢弃第一次 ADC 结果，再平均四次，降低复用器残留与采样保持串扰。

```text
normalized = (raw - background) * 1000 / (target_line - background)
normalized = clamp(normalized, 0, 1000)
```

分子与分母必须是有符号数。每一路标定跨度至少 32 ADC count，否则整组归一化无效。

### 10.7 寻线误差与方向 PID

当前实车假定 G0 在左、G7 在右，权重为：

```text
[7, 5, 3, 1, -1, -3, -5, -7]
error_percent = weighted_sum * 100 / (normalized_sum * 7)
```

线在左侧时误差为正，对应正的左转目标角速度。误差滤波为 `0.65*old + 0.35*new`。方向环沿用参考工程的离散微分量级：

```text
output = Kp*filtered_error
       + Ki*integral(filtered_error*dt)
       + Kd*(filtered_error - previous_error)
target_yaw_rate = output / 8000 * 60 deg/s
```

PID 输出限幅 `+/-8000`，积分限幅 `+/-80 percent*s`，使用条件积分抗饱和。注意这里的 Kd 乘离散误差差值，不再除以 dt，因此 `Kd=350` 的量级不能直接与标准连续微分系数比较。

### 10.8 差速限制与丢线状态机

寻线时角速度环输出的差速修正限制为：

```text
abs(correction) <= abs(base_speed) * differential_ratio
left_target  = base_speed - correction
right_target = base_speed + correction
```

默认比例 0.65。盲转期间临时放宽到 1.0，允许内轮降到零但不强制反转。若任一轮目标超过 600 mm/s，两轮按同一比例缩小，保持曲率。

状态机如下：

| 状态 | 数值 | 行为 |
| --- | ---: | --- |
| WAIT_LINE | 0 | 启动后尚未看到有效线 |
| TRACKING | 1 | 正常重心与方向 PID |
| GAP_HOLD | 2 | 无可靠转向记忆时保留旧命令最多 150 ms，不继续积分 |
| BLIND_TURN | 3 | 350 ms 内见过边缘或大偏差时，按记忆方向以 90 deg/s 盲转，最多 1200 ms |
| LOST | 4 | 恢复超时或标定无效，上层立即停车 |

目标线归一化总和小于 200 判为不可见。G0/G7 达到 550 或误差绝对值达到 35% 会刷新转向记忆。盲转重新捕获要求同时有效的通道数为 1..4，并连续两次 20 ms 采样成立；五路以上常表示仍压在直角交叉的宽线区域，不能过早退出盲转。

### 10.9 正方形状态机

直行阶段按左右编码器平均距离计算剩余量：

```text
remaining = 1000 mm - average_progress
speed_command = clamp(1.2 * remaining, -200, 200) mm/s
```

剩余超过容差但命令绝对值小于 40 mm/s 时保持最低 40 mm/s。距离误差不超过 10 mm、平均速度不超过 25 mm/s、航向误差不超过 1 deg、角速度不超过 4 deg/s，并连续稳定 400 ms 后进入左转。每段直行超时 30 s，每次转向超时 10 s。

## 11. 从零开始调参

调参必须从内环到外环。任何外环调参前，先锁定其下游内环；否则无法判断曲线差是当前参数还是下层执行器造成。

### 11.1 机械、电气与符号检查

1. 检查轮胎、轴承、减速箱是否卡滞，左右轮离地空转阻力是否接近。
2. 测量电机电池静态和带载电压，排除供电跌落。
3. 使用原始 MOTOR 小占空比测试四个方向，并验证零命令立即停车。
4. 手转左轮向前，左编码器累计应按预期正向变化；右轮同理。
5. 车辆左转时实际角速度必须为正，右转必须为负。符号错误先修坐标，禁止用负 Kp 掩盖。
6. 目标线放到 G0 时，寻线目标角速度必须为正，且左轮目标小于右轮目标。

### 11.2 标定电机死区

按第 6.8 节逐方向测启动值和运行值，记录当时电池电压与落地载荷。启动值显著高于运行值时才考虑短时启动补偿；两者相同时只需要静态前馈映射，甚至可以像当前工程一样先关闭前馈直接调 PI。

若四个方向都出现近似 50% 的巨大门槛，优先检查 H 桥快/慢衰减、PWM 真值、占空比是否取反和电机电源，而不是先更换四个电机。

### 11.3 标定编码器

1. 清零累计值，分别让每个轮子手动转 10 圈，记录计数并除以 10。
2. 让车辆沿直线实际走 1 m，记录左右计数，多次往返取平均。
3. 将 count/m 写入编码器模块；正方形距离模块也必须使用同一标定。
4. 用下式交叉核对有效轮径：`diameter = counts_per_rev / counts_per_meter / pi`。

本车数据：左 10 圈 3914，右 10 圈 3873；左/右 1 m 均为 1867。得到单圈 391.4/387.3，有效轮径约 66.73/66.03 mm。旧 STM32 的 7514/7263 count/m 使用不同计数倍频，禁止沿用。

### 11.4 调速度环

1. 架空后低速确认，再落地调参。
2. 暂时关闭死区前馈、角速度环和外层方向环，只给左右轮相同阶跃目标。
3. 输出限幅必须为 `+/-100%`，目标速度先用 100..200 mm/s。
4. 令 Ki=Kd=0，从小到大加 Kp，直到响应足够快但还未持续振荡。
5. 把 Kp 从临界值降低约 20%，再逐步增加 Ki，消除稳定误差。
6. 小车速度环通常不需要 D；噪声较大时 D 反而放大编码器抖动。
7. 同时比较左右目标/实际，检查输出是否长时间饱和和电池是否下跌。

本车最终两侧均为 `4000/800/0`。若需要把 Kp 加到约 35000 才跟随，先检查编码器 count/m、单位换算、输出限幅、控制周期和 OLED 阻塞，不能直接认定电机需要超大 Kp。

### 11.5 调角速度环

1. 锁死已调好的左右速度 PI。
2. 架空或在安全空地给正负小阶跃，例如 `+30/-30 deg/s`。
3. 先令 Ki=Kd=0、保留或暂时关闭 Kff，从小到大增加 Kp。
4. 确认目标与实际同号；若反号并越转越快，这是正反馈符号错误，不是增益不足。
5. 增加 Kff 让稳态输出更接近所需差速，再用 Kp 修正扰动。
6. 只在存在稳定偏差时少量增加 Ki，并观察积分限幅与饱和释放。
7. 有明显快速振荡且传感器噪声可控时再小量增加 Kd。
8. 正负方向、原地转和带前进速度转弯都要复测。

当前起点与实车值为 `1000/2000/0/1205`。VOFA 看 `I34/I35/I36`，并看 `I37/I38/I39` 区分前馈、PID 与最终差速。

### 11.6 调遥控航向环

1. 锁死速度环和角速度环。
2. 使用网页自动航向阶跃，先用 15..30 deg 小阶跃。
3. 看 `I5` 参考航向和 `I6` 实际航向，不要只拿最终 `I4` 与实际比较后误判限速过程。
4. Kff 决定参考运动时的基础角速度，Kp 修正航向跟踪误差，Kd 使用参考角速度与实际角速度之差抑制超调。
5. 逐步提高 Kp 到响应清晰，再加 Kd 抑制超调，最后调整 Kff 与 80 deg/s 参考限速。
6. 测试正负阶跃、跨越 `+/-180 deg` 和带前进速度直行保持。

当前参数 `4.000/0.300/1.000、80 deg/s` 已接受并锁定。

### 11.7 调寻线方向环与差速

1. 完成对应颜色模式的背景、目标线标定，确认八路归一化方向一致。
2. 架空做 G0/G7 符号检查。符号反了就整体反转通道权重，不能填负 Kp。
3. 保持基础速度 200 mm/s、Ki=0、Kd=0、差速 0.650。
4. 从较小 Kp 开始落地跑直线和缓弯，增加到开始左右摆动，再降低 20..30%。
5. 小步增加 Kd 抑制摆动和进入弯道时的冲击。
6. 只有长期存在同向稳态偏差才加很小 Ki，同时观察积分限幅。
7. PID 可稳定跟线后，再调差速比例。直角弯转不过去可适量增加；弯中内轮过慢、车身抖动或直线易摆则减小。
8. 单独测试窄缺口、直角交叉、左右 90 度和真正离开赛道，核对 `I63..I65` 状态机。

默认 `200/0/350、0.650` 已能工作，但赛道材质、光照、传感器高度和基础速度改变后应重新验证。

### 11.8 验证正方形和电压

正方形不是独立 PID 调参工具，而是前述四个环和编码器距离的综合验收。记录每边距离误差、每次转角误差、最终闭合误差和电池电压。电压显示必须先用万用表标定修正系数，再考虑增加欠压停车逻辑。

## 14. 调试故障复盘与避免方法

### 14.1 电机必须到约 60% 才转

最初测得四个方向都在 57..58% 附近，且把同一驱动接到旧电机后现象仍相同。这种高度一致性不符合四台机械系统独立死区，更符合软件使用了 AT8236 快衰减。改成慢衰减后门槛降为 7..8%。遇到类似问题，应依次检查衰减模式、PWM 真值、占空比取反、VM 电源、供电压降和机械阻力。

### 14.2 曲线目标与实际差很多，需要 Kp=35000

旧 STM32 工程的 7514/7263 count/m 被直接带入时，本工程测得速度约缩小四倍，PID 只能靠异常大增益追赶。改用实测 1867 count/m 后，参考参数 4000/800/0 恢复正常。不同 MCU 定时器的单边沿、双边沿、四倍频不可混用。

### 14.3 轮子周期性停一下

OLED 位带全屏刷新每约 200 ms 阻塞控制循环。编码器脉冲在阻塞期间累积，而旧代码仍按固定 10 ms 换算，制造假速度尖峰，PI 随后周期性削减 PWM。解决方法是停用暂不需要的 OLED，并用真实 elapsed_ms 计算速度；任何新外设都不能长时间阻塞 10 ms 控制任务。

### 14.4 角速度曲线越调越发散

实测目标 `+12.0 deg/s` 时反馈跑到 `-316.5 deg/s`，这是反馈极性相反造成的正反馈。修复是在所有 GZ 到车体角速度的路径统一乘 `-1`，不是继续减小或增大 PID。调环前必须先做正负方向阶跃。

### 14.5 上位机设置 200，目标仍只有 120

当时固件和网页存在旧的目标限幅/比例路径，设置值没有完整传到控制目标。当前最大角速度由 `YAWRATE` 回读，目标在串级控制入口按同一上限截断；修改上限后必须同时看配置回读与 `I34` 实际目标。

### 14.6 PID 输入点击应用后又变回去

旧网页每收到遥测就覆盖输入框，即使用户正在编辑或等待固件确认。当前使用“表单 dirty + pending 参数 + 遥测回读相等”三态：编辑时不覆盖，应用后等待确认，确认后才恢复自动同步。增加新调参项时必须沿用这一所有权规则。

### 14.7 摇杆不能动，独立电机可以动

这说明 PWM 和电机硬件大概率正常，问题位于 DRV 命令下行、模式条件、看门狗或闭环目标。排查顺序应是桥接 FFE2、固件 ACK/遥测、DRV 目标、编码器符号、IMU 条件，不能因为 MOTOR 能动就继续反复改 H 桥。

### 14.8 蓝牙频繁断联

历史问题由三个因素叠加：单次 GATT 写超时向外传播并关闭 WebSocket；9600 波特率遥测过密；Windows 偶尔返回不完整特征表。当前桥接隔离写失败并自动重连，固件降低遥测频率，且只接受 FFE1+FFE2 完整连接。仍断联时检查模块供电、是否被手机占用、距离与 Windows 蓝牙适配器。

### 14.9 VOFA 出现莫名尖峰或目标航向看不到

VOFA 的 I0/I1 是“同一行数值位置”，报文前缀不会创建独立通道组。把 TEL、SPD、LIN 直接分别送入会让不同语义反复占用 I0。当前桥将所有消息合并为固定 66 值 `tuning:` 行。后续增加信号时只能扩展固定映射，不能另发不同长度 FireWater 行。

### 14.10 蓝白模式归一化反了

蓝色 ADC 大、白色 ADC 小，`line-background` 为负。若用无符号数会下溢并全部夹到错误端。当前逐通道使用有符号差值，始终把背景映射为 0、目标线映射为 1000。

### 14.11 按 K1 却采集了另一种颜色

厂家资料的 K1/K2 引脚顺序与实板相反。实板已经确认 K1=PB15、K2=PB14。硬件行为优先于旧引脚表，并应在单一 `board_io` 映射表中修复，不能在应用逻辑里再次交换语义。

## 15. 维护与回归检查

每次修改控制、通信或模块结构后，至少完成以下回归：

1. Keil 全量构建 `0 Error(s), 0 Warning(s)`。
2. 上电静止约 3 s，确认 IMU 两声成功提示。
3. `HELP` 有 ACK，`ENCZERO` 能清零，网页参数不会自行回退。
4. 架空验证原始左右轮正反、零命令和 500 ms 看门狗。
5. 验证编码器正负、左/右转角速度符号和实际 90 度相对角。
6. 查看八路原始灰度，分别完成两种 SW1 模式标定。
7. 验证 G0/G7 寻线符号、短缺口、直角弯与真正丢线停车。
8. 检查 VOFA 固定通道没有换位，尤其是 `I4/I6、I15/I16、I34/I35、I55/I56`。
9. 检查浏览器失焦、断连、STOP、本地按键都能停车。
10. 在电池不同电量下复测，不把供电变化误判为 PID 变化。

不要让协议模块、网页和控制器各自保存一份“当前参数”。固件应用层是最终状态所有者，网页只能在用户编辑时暂时拥有表单，之后必须以固件回读确认。新增外设任务必须非阻塞，或至少用真实 elapsed_ms 参与所有时间相关计算。
