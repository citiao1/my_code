# K1/K2 发车各自独立参数集 实施计划

## 一、任务摘要

使 K1、K2 发车各持有一套**完整的 `MID_Param_t` 参数集**（PID 三环 + 运动参数 + 使能标志），发车时加载对应那套；VOFA 运行中改的是当前活动 `g_param`，下次同模式发车时重载代码内默认集（VOFA 改的值丢失）。

## 二、用户确认的关键决策

1. **参数范围**：全部 `MID_Param_t` 字段（pid_pos / pid_yaw / pid_speed_l / pid_speed_r 全部增益 + chassis_vx + speed_max + gyro_offset + enable_*），两套完全独立。
2. **VOFA 持久化**：VOFA 写当前活动 `g_param`，下次发车重载默认集（不保留 VOFA 改的值）。

## 三、当前状态分析（Phase 1 探索结果）

### 3.1 现有参数机制

- 单一全局 `g_param`（`MID_Param_t`）承载所有参数，`MID_Param_Init()` 在上电时初始化（enables=0，安全停止态）。
- `__chassis_vx = 120.0f`、`__kp = 39.0f` 为全局基值（mid_pid.c 定义，mid_pid.h extern）。
- K1 发车（`s_handle_start`）临时硬编码 `g_param.pid_pos.kp = 52;` —— 覆盖全局，会冲掉 VOFA 调的值。
- K2 发车（`s_handle_k2_start`）临时 `g_param.pid_pos.kp = __kp;` —— 恢复默认。
- 发车速度由 `__chassis_vx + offset` 宏区分（mid_key.h 的 `MID_KEY_K1_LAUNCH_OFFSET` 等）。
- 速度渐变（ramp）在 `mid_chassis.c::MID_Chassis_RampStep`，目标值引用 `__chassis_vx`。
- VOFA（`app_debug.c::s_process_line`）直接写 `g_param` 各字段。

## 四、设计核心

### 4.1 两套默认参数集（const，编译期常量）

在 mid_pid.c 新增两个 `static const MID_Param_t`：
- `s_param_k1_default`：K1 模式完整参数集
- `s_param_k2_default`：K2 模式完整参数集

每套字段全部显式赋值（不依赖零初始化），其中：
- **chassis_vx** = 该模式的**巡航速度**（ramp 收敛目标），初值均取 `120.0f`（= 现 `__chassis_vx`，保持行为不变，用户后续可各自调整）
- **enable_*** = 1（发射就绪态；`MID_Chassis_Start` 也会置 1，此处仅为语义完整）
- 其余字段见下方"默认值表"

### 4.3 巡航速度保存机制

- 在 mid_key.c 新增 `static float s_cruise_vx = 0.0f;`
- K1/K2 发车时：`LoadXxxDefaults()` 后 `s_cruise_vx = g_param.chassis_vx;`（保存模式巡航速度），再 `g_param.chassis_vx = s_cruise_vx + LAUNCH_OFFSET;`
- 新增 `MID_Key_GetCruiseVx(void)` getter，供 `MID_Chassis_RampStep` 读取模式巡航速度作为 ramp 目标。

### 4.4 数据流

```
上电: MID_Param_Init() → g_param (enables=0, IDLE 态)
        ↓
K1 发车: MID_Param_LoadK1Defaults() → g_param (memcpy K1 默认集)
         s_cruise_vx = g_param.chassis_vx          ← 保存巡航速度
         g_param.chassis_vx += K1_LAUNCH_OFFSET     ← 发车速度
         MID_Chassis_Start() → enables=1
         运行中 VOFA 改 g_param.xxx (临时生效)
         运行中 MID_Chassis_RampStep 用 s_cruise_vx 作 ramp 目标
        ↓
K1 停止: MID_Chassis_Stop() → enables=0, chassis_vx=0
        ↓
下次 K1 发车: MID_Param_LoadK1Defaults() → g_param (VOFA 改的值丢失，重载默认)
```

## 七、假设与决策

1. **K1 默认集字段值**：除 `pid_pos.kp=52`（来自现有 mid_key.c:93）外，其余字段均取原 `MID_Param_Init` 当前值。用户可随时编辑 `s_param_k1_default` 调整。

3. **enables 在默认集中置 1**：语义为"发射就绪"；`MID_Chassis_Start` 也会置 1，二者一致，无冲突。
4. **gyro_offset 在默认集中置 0**：发车时 `MID_IMU_CalibrateGyro` 会覆盖，初值无影响。
5. **停止时 `s_cruise_vx` 归零**：避免 IDLE 态返回旧值误导 ramp（ramp 在 IDLE 态本就不动作，归零仅为语义清晰）。
6. **删除 `__chassis_vx` / `__kp` 全局**：两套默认参数集已成为参数唯一来源，全局基值冗余。`MID_Param_Init` 改为复用 K2 默认集（字段值与原实现完全一致，仅 enables 强制改 0），行为不变。
7. **`MID_Param_Init` 复用 K2 默认集而非 K1**：原 `MID_Param_Init` 的 `pid_pos.kp=__kp=39` 与 K2 默认集一致，故选 K2；上电态 enables=0，PID 值不影响控制（电机停止），耦合无害。
8. **编码**：所有被修改文件均为 GB2312，修改后保持 GB2312。
