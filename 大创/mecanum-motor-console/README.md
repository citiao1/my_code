# BM50 VGT6 纯蓝牙控制台

当前 R7：四轮速度环参数固定为 A/B/C/D=`1.2/0.0991/0`、
`1.2/0.0998/0`、`1.2/0.0998/0`、`1.2/0.1008/0`；角速度环为 PI，方向环
为 PD。页面支持查询、写入、回读角环参数和目标，单轮“写入目标”只发送
目标 RPM。默认目标上限为 200 RPM，
允许调低但不能超过 200。

依据本地 BM50 规格书 PDF 第 4～5 页：按程序当前的 19:1 减速比，4462 RPM 额定本体转速约对应 235 RPM 输出轴转速，5199 RPM 空载约对应 274 RPM；选 200 RPM 留余量。此结论以实际电机确为 19:1 减速箱为前提。

注意：速度环仍保留独立的 ±60% PWM 输出限制。目标提高到 200 不保证实际速度能达到 200。若目标高于实际、VOFA I9～I12 对应轮输出持续贴着 ±60，则是输出饱和；驱动层并没有再乘一次 60%，点动 30% 限幅也不作用于速度环。当前版本没有提高 PWM 上限。

本目录现在保留 BM50 速度环和 R7 姿态级联调试功能：

- BLE 扫描、连接、断线重连；
- `ARM`、`STOP`、速度环开关；
- 四路目标 RPM 设置和当前 Kp/Ki/Kd 显示；
- `TEL` 实时速度反馈。
- 角速度 PI、方向 PD 参数面板、回读和启动；
- `ATEL` 角环遥测、目标/实际波形、航向归零和 IMU 校准。

已移除摄像头、摇杆遥控和香橙派控制页面。串口桥仍由本地 Python 进程独占 BLE，网页只通过 `ws://127.0.0.1:8766` 发命令。

使用 `启动上位机.bat`，可输入 BLE 设备名或地址；直接回车会扫描 `FFE0` 服务以及常见 UART 模块名称（BT05、HC-08、BLE、UART 等）。连接后先让四轮悬空，再依次点击 `ARM`、`启用速度环`。

若仍无法连接，先关闭手机蓝牙调试 App 和其他 BLE Central；FFE0 模块同一时间只能被一个 Central 占用。

## 本次链路重构

- 下位机只按真实 CR/LF 结束命令，不再把 UART IDLE 当成命令结束。BLE 的 16 字节分包不再拆断 PID 等命令。
- 网页发送命令后等待下位机 ACK/查询结果，桥接将命令逐条串行执行。无应答会明确报告具体命令，不自动重发电机命令。
- `STOP` 会取消旧的排队目标；停机保留 ARM，下次可以直接重新启用速度环。启用失败时不继续发送目标，四轮目标写入中途失败时尝试 STOP。
- 写入上限使用 `SPDLIMIT,<rpm>`，避免 `SPEED,1` 既代表启用又代表 1 RPM 的歧义；`ACK,SPEED,LIMIT` 不再错误地把网页速度环状态改为关闭。
- 连接时依次查询 `VER`、`UART`、`LINK`、`STACK`、`SPEEDLIMIT`、
  `SPEEDSTATUS`、`PIDGET`、`CAPS`、`YAWGET`、`HEADGET`、`ANGLESTATUS`、`STACK`，
  不自动开启周期遥测。速度环启动会开启
  遥测，或手动选择“周期遥测：开启”。
- 周期 TEL 为 300 ms，控制算法仍为 10 ms。只有已开启周期遥测但超过 3 秒未收到完整 TEL 才报超时；STOP、关闭遥测、单次状态查询均不会误报。
- 页面显示固件版本、链路计数、UART 错误分类、栈水位和最近 12 条命令/应答，不记录周期 TEL，避免刷屏。`ERR,UNKNOWN_COMMAND,...` 回显下位机收到的命令，随后 `RXHEX` 给出原始字节。

## R4 栈修复与错误恢复

旧固件启动栈只有 1024 字节，Keil 静态调用图已有 1808 字节的已知路径，尚未计入完整间接调用和中断开销。本版通过 `.ioc` 和 CubeMX 生成，将栈增至 4096 字节，同时减少遥测格式化的嵌套栈占用。这是确认存在的配置缺陷，但不能仅凭编译认定截图中的 UART 乱码已经实机解决。

桥接每条命令前后都发送 LF，UART IDLE 仍不结束命令。发生 UART 错误时，下位机丢弃未完成的行，等待换行重新同步，不会将错误前后的字节拼成电机指令。没有自动重发启动或目标指令，也不会将 `3PEED` 猜测修正成 `SPEED`。

栈保护异常时下位机制动、撤销 ARM 并关闭遥测，上位机禁用运动按钮；STOP 和诊断查询仍可使用。固件版本不匹配时也禁用运动按钮。

## 更新后必须重启桥接

关闭旧桥接窗口，再运行 `启动上位机.bat`，然后刷新页面。只刷新网页或只烧录 HEX 不会让已运行的 Python 进程加载新代码。

新版网页会检查桥接握手和 `VGT6_BM50_ATTITUDE_R7`。遇到旧桥接或旧固件时禁用控制并提示重启，不会把新版网页请求错误地透传给下位机。启动脚本发现端口已占用时会显示旧进程 PID，不会自动结束进程。

连接后固件版本应显示 `VGT6_BM50_ATTITUDE_R7`，栈分配应为 4096 B，
保护正常，目标上限查询应返回 `SPEEDLIMIT,200`（或你设置的更低值）。
让四轮悬空，填写较低的目标 RPM，再 `ARM` → `启用速度环`。点击 STOP 后可再次
启动，无须断开蓝牙。

角环测试需先 `ARM` 并启用速度环，再启动角速度环或方向环。页面会持续发送
`KEEP`，因此不会触发固件的 1.5 秒角环看门狗；点击 STOP 后可直接再次启动。

`LINK` 返回：

```text
LINK,RX字节数,完整命令数,RX溢出次数,TX丢弃次数,UART错误次数,周期遥测0或1
```

如果“查询状态”正常而周期 TEL 超时，检查最后一项是否为 1；溢出、丢弃、串口错误计数持续增长时，把“最近命令与应答”和 LINK 一起记录。

R4 还会显示以下查询结果：

```text
UART,波特率,PCLK_Hz,BRR,最后错误标志,PE次数,NE次数,FE次数,ORE次数,DMA次数
STACK,分配字节,已用水位字节,剩余字节,保护0或1
RXHEX,未知命令原始字节的十六进制
```

PCLK 是软件配置值，不是仪器测得的物理时钟。STACK 是已观察到的水位，不是所有运行路径的上限证明。如果仍收到 `3PEED` 等乱码，请保留 UART、STACK 和 RXHEX；FE/NE/ORE 的变化可进一步定位串口接收问题。

## VOFA

与旧 `vehicle-console` 一样使用 FireWater：

- 数据引擎：TCPClient；
- 地址：`127.0.0.1`；
- 端口：`1347`；
- 协议：FireWater；
- 在网页开启周期遥测或启动速度环后才有连续数据。

输出为 `vehicle:<数字CSV>\r\n`，固定 14 个通道：

| 通道 | 内容 |
| --- | --- |
| ch0 / I0 | 下位机时间 ms |
| ch1～ch4 / I1～I4 | A/B/C/D 实际速度 RPM |
| ch5～ch8 / I5～I8 | A/B/C/D 目标速度 RPM |
| ch9～ch12 / I9～I12 | A/B/C/D 有符号输出 % |
| ch13 / I13 | 电池电压 mV |

VOFA 发送的换行结尾文本命令也会经同一应答队列转发给下位机。桥接仅输出当前 BM50 27 字段 TEL，不混用旧车型的通道格式。

角环使用 `ATEL`，桥接输出为 `attitude:<数字CSV>\r\n`，固定通道如下：

| 通道 | 内容 |
| --- | --- |
| I0 | 时间 ms |
| I1 / I2 | 目标 / 实际角速度 °/s |
| I3 | 角环输出 RPM |
| I4 / I5 | 目标 / 实际航向 ° |
| I6 | 航向误差 ° |
| I7 | 方向环输出角速度 °/s |
| I8 | 限幅标志 |
| I9 | 速度环使能 |
| I10 | 电池电压 V |
