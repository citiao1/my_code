## 本次链路重构

- 下位机只按真实 CR/LF 结束命令，不再把 UART IDLE 当成命令结束。BLE 的 16 字节分包不再拆断 PID 等命令。
- 网页发送命令后等待下位机 ACK/查询结果，桥接将命令逐条串行执行。无应答会明确报告具体命令，不自动重发电机命令。
- `STOP` 会取消旧的排队目标；停机保留 ARM 和当前周期遥测，下次可以直接重新启用速度环。用“周期遥测：关闭”或 `TEL,0` 显式停止遥测。启用失败时不继续发送目标，四轮目标写入中途失败时尝试 STOP。
- 写入上限使用 `SPDLIMIT,<rpm>`，避免 `SPEED,1` 既代表启用又代表 1 RPM 的歧义；`ACK,SPEED,LIMIT` 不再错误地把网页速度环状态改为关闭。
- 连接时依次查询 `VER`、`UART`、`LINK`、`STACK`、`SPEEDLIMIT`、
  `SPEEDSTATUS`、`PIDGET`、`CAPS`、`YAWGET`、`HEADGET`、`ANGLESTATUS`、`STACK`，
  `HLOG,STATUS`，不自动开启周期遥测。速度环启动会开启
  遥测，或手动选择“周期遥测：开启”。
- 周期 TEL 为 300 ms，控制算法仍为 10 ms。只有已开启周期遥测但超过 3 秒未收到完整 TEL 才报超时；STOP、关闭遥测、单次状态查询均不会误报。命令发送期间按钮保持稳定显示，避免整页闪烁。
- 页面显示固件版本、链路计数、UART 错误分类、栈水位和最近 12 条命令/应答，不记录周期 TEL，避免刷屏。`ERR,UNKNOWN_COMMAND,...` 回显下位机收到的命令，随后 `RXHEX` 给出原始字节。

## R4 栈修复与错误恢复

旧固件启动栈只有 1024 字节，Keil 静态调用图已有 1808 字节的已知路径，尚未计入完整间接调用和中断开销。本版通过 `.ioc` 和 CubeMX 生成，将栈增至 4096 字节，同时减少遥测格式化的嵌套栈占用。这是确认存在的配置缺陷，但不能仅凭编译认定截图中的 UART 乱码已经实机解决。

桥接每条命令前后都发送 LF，UART IDLE 仍不结束命令。发生 UART 错误时，下位机丢弃未完成的行，等待换行重新同步，不会将错误前后的字节拼成电机指令。没有自动重发启动或目标指令，也不会将 `3PEED` 猜测修正成 `SPEED`。

栈保护异常时下位机制动、撤销 ARM 并关闭遥测，上位机禁用运动按钮；STOP 和诊断查询仍可使用。固件版本不匹配时也禁用运动按钮。

## VOFA

与旧 `vehicle-console` 一样使用 FireWater：

- 数据引擎：TCPClient；
- 地址：`127.0.0.1`；
- 端口：`1347`；
- 协议：FireWater；
- 在网页开启周期遥测或启动速度环后才有连续数据。

输出为 `vehicle:<数字CSV>\r\n`，固定 14 个通道：

| 通道 | 内容 |
| --- | --- |
| ch0 / I0 | 下位机时间 ms |
| ch1～ch4 / I1～I4 | 电机 1/2/3/4 实际速度 RPM |
| ch5～ch8 / I5～I8 | 电机 1/2/3/4 目标速度 RPM |
| ch9～ch12 / I9～I12 | 电机 1/2/3/4 有符号输出 % |
| ch13 / I13 | 电池电压 mV |

VOFA 发送的换行结尾文本命令也会经同一应答队列转发给下位机。桥接仅输出当前 BM50 27 字段 TEL，不混用旧车型的通道格式。

角环使用 `ATEL`，桥接输出为 `attitude:<数字CSV>\r\n`，固定通道如下：

| 通道 | 内容 |
| --- | --- |
| I0 | 时间 ms |
| I1 / I2 | 目标 / 实际角速度 °/s |
| I3 | 角环输出 RPM |
| I4 / I5 | 目标 / 实际航向 ° |
| I6 | 航向误差 ° |
| I7 | 方向环输出角速度 °/s |
| I8 | 限幅标志 |
| I9 | 速度环使能 |
| I10 | 电池电压 V |
