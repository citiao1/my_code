## 2. 控制器上的 PS2 接口

原理图中的 PS2 专用连接器为 `CN4`，对应网络名为：

| CN4 网络 | 作用 |
|---|---|
| `3V3` | 接收器电源 |
| `GND` | 电源地，必须与 STM32 共地 |
| `PE15` | `DI/DAT`，接收器发送给 STM32 的数据输入 |
| `PE12` | `DO/CMD`，STM32 发送给接收器的命令输出 |
| `PE10` | `CS/SEL`，片选，低有效 |
| `PE8` | `CLK`，同步时钟 |

推荐接线表：

| PS2 接收器信号 | 控制器 CN4 |
|---|---|
| `VCC` 或 `VDD` | `3V3` |
| `GND` | `GND` |
| `DI`、`DAT` | `PE15` |
| `DO`、`CMD` | `PE12` |
| `CS`、`SEL` | `PE10` |
| `CLK` | `PE8` |
| `ACK` | 不接 |
| `NC` | 不接 |

注意事项：

1. 接收器使用 `3.3 V` 供电，不能直接接 5 V。
2. 必须先断电，再插拔接收器。
3. `ACK` 在现有资料示例中未参与通信，不需要占用额外 GPIO。
4. 如果接收器外壳上的针脚编号与资料不同，应以信号名称和万用表确认结果为准。

## 4. PS2 通信协议摘要

PS2 接收器是同步串行设备：

- `CS/SEL` 拉低后开始一帧传输。
- 每个字节 8 bit。
- LSB 先传。
- 时钟频率约为 `250 kHz`。
- 主机在时钟线上产生脉冲，同时发送命令并读取 `DAT`。
- 一帧结束后拉高 `CS`，并留出足够的帧间隔。

最基本的轮询帧为 9 字节：

```text
01 42 00 00 00 00 00 00 00
```

典型返回数据：

| 字节下标 | 含义 |
|---:|---|
| `0` | 返回空闲字节，通常为 `0xFF`，不可校验为主机命令 `0x01` |
| `1` | 模式 ID，常见为 `0x41`、`0x73`、`0x79` |
| `2` | 固定标志，通常为 `0x5A` |
| `3` | 数字按键低字节 |
| `4` | 数字按键高字节 |
| `5` | 右摇杆 X |
| `6` | 右摇杆 Y |
| `7` | 左摇杆 X |
| `8` | 左摇杆 Y |

数字按键为低有效：对应位为 `0` 表示按下，`1` 表示未按下。常见按键位如下：

| 返回字节 | bit | 按键 |
|---:|---:|---|
| `3` | 0 | `SELECT` |
| `3` | 1 | `L3` |
| `3` | 2 | `R3` |
| `3` | 3 | `START` |
| `3` | 4 | `UP` |
| `3` | 5 | `RIGHT` |
| `3` | 6 | `DOWN` |
| `3` | 7 | `LEFT` |
| `4` | 0 | `L2` |
| `4` | 1 | `R2` |
| `4` | 2 | `L1` |
| `4` | 3 | `R1` |
| `4` | 4 | `TRIANGLE` |
| `4` | 5 | `CIRCLE` |
| `4` | 6 | `CROSS` |
| `4` | 7 | `SQUARE` |

摇杆值通常以 `128` 附近为中心，范围约为 `0..255`。实际使用前应记录手柄静止时的中心值，并做死区和限幅处理。

## 5. 模拟模式初始化

不同接收器的上电状态可能不同。建议在驱动初始化时按资料中的流程执行：

1. 上电后等待接收器稳定。
2. 连续发送几次基础轮询帧，确认能收到有效响应。
3. 发送 `0x43` 进入配置模式。
4. 发送 `0x44` 设置模拟/震动模式。
5. 再发送 `0x43` 退出配置并保存。
6. 后续周期发送 `0x42` 轮询数据。

控制逻辑至少应检查：

- 返回帧长度完整；
- 模式 ID 和 `0x5A` 标志正确（首字节不能要求等于主机命令 `0x01`）；
- 模式 ID 是允许的模拟模式，通常优先接受 `0x73` 或 `0x79`；
- 连续通信超时或校验失败时立即输出停车目标。

## 6. 推荐软件分层

建议以后新增以下模块，保持底层通信和运动控制分开：

```text
Bsp/Inc/ps2.h
Bsp/Src/ps2.c
App/Inc/ps2_control.h
App/Src/ps2_control.c
```

### `ps2.c`

只负责硬件和协议：

- 初始化 `PE8/PE10/PE12/PE15`；
- 产生 GPIO 时序；
- 发送和接收一个字节；
- 发送初始化命令；
- 轮询 9 字节数据；
- 保存最近一次有效帧、模式和超时状态。

底层模块不应直接控制电机，也不应直接修改 PWM。

### `ps2_control.c`

只负责输入解释和安全策略：

- 读取 PS2 快照；
- 对摇杆做中心校准、死区、比例和限幅；
- 把摇杆转换为底盘的前后、横移和旋转目标；
- 处理 `START` 解锁、`SELECT` 停车锁定；
- 检查掉线、无效帧和模式错误；
- 将目标交给现有底盘/速度控制接口。

速度控制、姿态控制和电机驱动仍由现有模块负责，PS2 模块不要绕过它们直接写比较寄存器。

## 7. 在 `vgt6_module_test` 中的接入位置

当前启动路径为：

```text
main()
  -> HAL 外设初始化
  -> App_Init()
  -> while(1) App_Process()
```

当前 `App_Init()` 会初始化串口、编码器、底盘测试、速度控制、姿态控制、显示和遥测；`App_Process()` 会处理串口命令、底盘测试、电池、遥测以及周期性的编码器、IMU 和控制环。

后续推荐的调用顺序：

1. 在 `App_Init()` 中调用 PS2 底层初始化和 `Ps2Control_Init()`。
2. 在 `App_Process()` 的周期任务中调用 `Ps2_Process()`，更新最近一次手柄快照。
3. 调用 `Ps2Control_Process()`，把手柄输入转换为底盘目标。
4. 让现有速度控制、姿态控制和底盘安全逻辑继续执行。
5. 任何异常路径都调用现有的停车/失能接口。

建议先实现固定周期轮询，例如 10 ms 或 20 ms；不要在主循环中使用无上限的阻塞延时。软件时序中的短延时只用于 PS2 一个字节的时钟脉冲，且应保证不会长时间阻塞电机安全处理。

## 8. 推荐控制映射

默认采用左摇杆控制平移、右摇杆控制旋转：

| PS2 输入 | 底盘目标 |
|---|---|
| 左摇杆 Y | 前进/后退 `forward` |
| 左摇杆 X | 左移/右移 `lateral` |
| 右摇杆 X | 左右旋转 `rotate` |

实现时应注意：

- 根据实车方向确认 X/Y 正负号，必要时单独取反；
- 对每个摇杆轴设置死区，避免中位抖动；
- 将 `0..255` 映射到有符号范围，再乘以最大速度比例；
- 在 `START` 未解锁、手柄掉线或 `SELECT` 停车时，三个目标全部置零；
- 初次调试时将最大速度和最大旋转速度限制在较低值。

## 9. 与蓝牙/上位机输入的关系

当前工程通过 `SerialDma_Init(Command_HandleLine)` 和 `SerialDma_Process()` 处理串口命令，现有串口路径可能同时承担蓝牙或上位机控制。

最终只使用 PS2 遥控时，必须保证两个输入源不会同时直接写运动目标。推荐采用以下策略之一：

1. PS2 模式下，串口只保留状态查询、参数读取和调试命令，不接受运动目标；
2. 增加明确的输入源选择状态，任何时刻只允许一个源拥有底盘控制权；
3. 如果串口命令超时或模式切换，先停车，再允许 PS2 重新接管。

不要让串口处理函数和 `Ps2Control_Process()` 在同一周期分别覆盖同一组目标变量。

## 10. 必须保留的安全逻辑

建议把以下规则写死在 PS2 控制层和底盘安全层中：

- 上电默认锁定，不能因为摇杆有偏移而自动起车；
- 只有检测到摇杆已回中后，`START` 才能解锁；
- `SELECT` 立即清零目标并锁定；
- 任何无效帧、模式错误、通信超时或接收器掉线都立即停车；
- 目标速度为零时仍保留底盘的制动/失能策略；
- 保留现有 `ChassisTest` 的 ARM、STOP、DISARM 约束；
- 控制器异常、栈健康检查失败或 IMU/编码器状态异常时，优先停车；
- 不允许通过手柄控制绕过速度限幅、姿态控制和电机使能逻辑。

## 11. 物理调试顺序

建议按以下顺序上电和测试：

1. 只连接 `3V3` 和 `GND`，确认接收器供电电压正确。
2. 确认手柄与接收器已经配对。
3. 使用逻辑分析仪或示波器检查 `PE10/PE8/PE12/PE15` 上的 `CS/CLK/CMD/DAT`。
4. 先只验证能读到设备 ID 和 `0x5A`，不连接电机负载。
5. 确认按键低有效逻辑和摇杆中心值。
6. 手柄回中后按 `START`，验证解锁条件。
7. 抬起小车，使车轮离地，低速验证四个轮子的方向。
8. 验证前进、横移、旋转的组合方向。
9. 最后在低速限制下接入正常电机负载，测试掉线和 `SELECT` 急停。

## 12. 交接结论

本工程的 PS2 接收器应接到控制器 `CN4`：

```text
3V3  -> VCC/VDD
GND  -> GND
PE15 -> DI/DAT
PE12 -> DO/CMD
PE10 -> CS/SEL
PE8  -> CLK
```

这四个信号脚目前在 `vgt6_module_test` 中空闲。后续实现应采用 GPIO 软件时序，新增独立的 PS2 驱动和控制层，并通过现有底盘/速度控制链路输出目标；不要直接复用 IMU 的 SPI1，也不要让 PS2、蓝牙和上位机同时改写运动目标。

  网页兼容版本、OLED、烧录读回标记统一更新至 R13。
- PS2 微秒延时会恢复 DWT 计时使能。pyOCD 退出调试时清除 `DEMCR` 不再让主循环
  卡在延时内；主机测试覆盖延时开始前及延时中途关闭计数器的情况。

R13 主机测试直接编译真实 PS2、航向、角速度和速度环，覆盖小横向分量、非 45°
斜向比例、保持角不随左杆更新、右杆双向转动及回中捕获、±180° 跨界、
高速斜向纠偏余量、IMU 失效停车、外部 STOP 后不自行重启和调试器退出恢复。
Keil 最终构建为 0 errors、0 warnings；网页 32 项、桥接 14 项及启动脚本回归通过。

全向输入的现场判别：`PS2RAW` 的第 8/9 个返回字节分别是左杆 X/Y，
