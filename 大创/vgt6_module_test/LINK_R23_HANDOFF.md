## 修复

1. 网页原先松键只修改待发向量，正在等待MOVE应答的flush可能迟至应答/超时后才处理STOP。现在松键立即走紧急STOP；MOVE失败也补发STOP。记录motion epoch，晚到的MOVE应答不能重新声明运动所有权或开启KEEP；快速再次按键仍可发送最新向量。JS v35支持R23；没有在实车发送非零运动命令来测试此路径，使用真实JS+模拟延迟应答回归证明。
2. 桥接控制目标入队后超过250ms拒绝执行，同一组连续运动只保留最新排队目标；普通排队命令超过3s也拒绝，STOP/DISARM保持优先取消旧请求。不会自动重试电机指令。
3. 广播给网页客户端的send有100ms上界，慢客户端被移除并关闭，其他观察者与MCU应答不再无限等待它；VOFA drain也有限时。保留原有“先发布原始状态、再完成匹配命令”的顺序。TOF/WLOG实时帧不再逐行刷桥接控制台。物理断连回调立即撤销在线标志、取消旧命令及续发，避免清理GATT期间页面仍报在线。
4. 下位机新增 `SerialDma_WriteTelemetry`：完整收到命令后的80ms内让出可选周期遥测；UART已有任何待发/正在发帧时跳过过时遥测，不累计待发实时画面。单次查询回复、ACK、HLOG/WLOG下载仍走原可靠FIFO。已经开始发送的完整串口帧不截断，无法消除其固有发送时长。
5. TOF本地预算33ms/间隔40ms/ready轮询2ms、100mm前进停止和200mm前进上限40RPM保持R22。有效距离显示仍为单流10Hz、与状态同开5Hz；连续相同无效状态只以1Hz保活，连接/状态/错误数变化或恢复有效后及时恢复上报。显式TOF查询不节流。繁忙时主动跳过部分显示帧，板载测量和前进保护持续运行。
6. 只读 `LINKQ,pending_frames,pending_bytes,telemetry_skipped,command_age_ms` 监测TX队列；主动跳过周期遥测单独计数，不混进UART错误或普通TX丢弃，也不会丢弃RAM日志样本。CAPS增加UART_QOS，VER/OLED/读回标记为R23。角环和轮速精确白名单加入R23，HLOG/WLOG方程、格式、采样校验未放宽。
