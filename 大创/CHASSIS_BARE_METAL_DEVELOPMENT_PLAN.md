# F407VET6 四驱麦轮蓝牙小车：裸机底盘开发计划

## 1. 本阶段目标与边界

本阶段只做底盘方案和实施计划，不编写代码、不新建工程、不迁移 RTOS。

最终目标是：使用 C30D STM32F407VET6 控制板、4 个带霍尔编码器的 MG513 电机和 4 个麦克纳姆轮，实现蓝牙遥控的前后、横移、斜移、原地旋转，并对四个车轮分别做速度闭环。

首版采用裸机协作式调度，目标控制频率为 100 Hz。功能稳定后，再保持模块接口不变迁移到 FreeRTOS。

## 2. 已核对的现有资料

### 2.1 `diansai_test`：建议作为首版工程基线

该工程面向准确的 `STM32F407VET6 / LQFP100`，有 `.ioc` 和 Keil MDK-ARM 工程，采用 STM32 HAL。

当前程序链路是：

```text
main()
  -> CubeMX 外设初始化
  -> Vehicle_Init()
  -> while (1) 中持续调用 Vehicle_Loop()
       -> 串口命令解析
       -> 每 10 ms 调用 VehicleControl_Update()
       -> 每 100 ms 发遥测
       -> 每 550 ms 发状态
```

底盘控制链路是：

```text
USART2 接收 DRV/PING/STOP
  -> 更新 throttle/steering 和命令时间戳
  -> 400 ms 通信超时检测
  -> 读取 TIM2/TIM3 编码器增量
  -> 估算左右轮速度
  -> 航向/转向控制
  -> 左右轮增量式 PID
  -> TIM9/TIM10/TIM11 输出双路 H 桥 PWM
```

可直接保留的能力：

- HAL + CubeMX 生成边界和 Keil 工程配置。
- 10 ms 裸机周期调度框架。
- USART2 中断逐字节接收、主循环解析的分工。
- `PING`、`STOP` 和 400 ms 失联停车机制。
- 电机零目标时清 PID 状态、PWM 限幅等安全行为。
- 电池检测、蜂鸣器、OLED、MPU6050 等现成板级功能；首轮底盘试车时可暂不启用非必要功能。

需要扩展的部分：

- 双电机状态和 PID 扩为四个独立轮实例。
- TIM4/TIM5 编码器和 TIM1 四路 PWM 加入 `.ioc`。
- 差速的 `throttle/steering` 解算替换为麦轮 `vx/vy/wz` 逆运动学。
- 蓝牙命令从二维输入扩为三自由度输入。

### 2.2 厂商 Mini 小车源码：作为四驱硬件和算法参考

该工程采用标准外设库 + FreeRTOS，已有完整四轮路径：

```text
Balance_task()，100 Hz
  -> 读取 TIM2/3/4/5 四路编码器
  -> 根据遥控来源生成 Move_X/Move_Y/Move_Z
  -> Drive_Motor() 做麦轮逆运动学
  -> 四个独立增量 PI
  -> Set_Pwm() 输出四组 H 桥 PWM
```

值得复用的内容：

- 四路电机与编码器的板载引脚映射。
- 麦轮四轮逆运动学的符号关系。
- 四轮目标速度统一限幅、输入平滑、每轮独立 PI 的处理顺序。
- 100 Hz 控制周期和 10 kHz PWM 配置。

不建议直接复用整个工程：

- 它已经使用 FreeRTOS，不符合首版裸机目标。
- 它基于旧标准外设库，不应与 `diansai_test` 的 HAL/CubeMX 生成代码混用。
- Keil 工程目标器件写的是 `STM32F407ZG`，而实板是 `STM32F407VE`；不能把该工程配置作为新工程的器件、存储布局或生成配置来源。
- 厂商的串口/CAN 指令丢失停车代码被注释，安全性不如 `diansai_test` 现有的 400 ms 看门狗。
- 车型由板载电位器自动选择，首版专用麦轮工程不需要这种多车型分支。

### 2.3 RM 项目 Markdown：只借鉴分层，不复用电机层

`RM_Fu`、`RM_Li` 面向 DJI CAN 电机，电机反馈和输出协议与 MG513 + AT8236 完全不同。可借鉴“输入层、底盘运动学、电机闭环、板级驱动分层”的思路，不复用 CAN 电机抽象、M3508 参数或 DR16 输入链路。

## 3. C30D 板底盘相关硬件映射

以下映射由原理图、`diansai_test.ioc` 和厂商源码交叉核对得到。

| 通道 | AT8236 输入 / PWM | 霍尔编码器 | 定时器资源 |
| --- | --- | --- | --- |
| Motor A | PB8、PB9 | PA15、PB3 | TIM10_CH1 + TIM11_CH1；TIM2_CH1/CH2 |
| Motor B | PE5、PE6 | PB4、PB5 | TIM9_CH1/CH2；TIM3_CH1/CH2 |
| Motor C | PE9、PE11 | PB6、PB7 | TIM1_CH1/CH2；TIM4_CH1/CH2 |
| Motor D | PE13、PE14 | PA0、PA1 | TIM1_CH3/CH4；TIM5_CH1/CH2 |

其他底盘相关资源：

| 功能 | 引脚 / 参数 | 计划用途 |
| --- | --- | --- |
| 蓝牙串口 | USART2：PD5 TX、PD6 RX，9600 baud | 接蓝牙模块，接收遥控命令和返回调试状态 |
| 使能开关 | PD3，上拉输入 | 软件电机总使能；低电平立即停车 |
| 电池采样 | PB0 / ADC | 欠压保护，阈值需按实际电池串数确定 |
| MPU6050 | PB10/PB11 / I2C2 | 首轮可不参与；后续可加车体航向保持 |
| PWM 周期 | ARR=16799、PSC=0 | 在 168 MHz 定时器时钟下约为 10 kHz |

板载 AT8236 的 ISEN 端通过电阻接地，原理图中没有接入 MCU ADC，因此首版不能声称具有软件电流闭环或堵转电流检测。台架阶段应使用限流电源或外部电流表，并依赖驱动芯片自身保护。

## 4. 建议的裸机软件架构

```text
Core/CubeMX 生成层
  GPIO / TIM1,2,3,4,5,9,10,11 / USART2 / ADC

BSP 板级层
  board_motor      四路 H 桥 PWM 和安全停止
  board_encoder    四路编码器计数快照、清零和方向配置
  board_bluetooth  USART2 接收环形缓冲与发送
  board_safety     使能开关、电池状态、总急停

Module 控制层
  wheel_speed      四个独立速度 PI、限幅、状态复位
  mecanum          vx/vy/wz 到四轮目标速度的逆运动学
  command          蓝牙命令、死区、斜坡、超时

Application 应用层
  chassis_init
  chassis_control_100hz
  telemetry_10hz
  main_loop
```

关键原则：

- 中断只收字节、记录计数或置标志，不在 ISR 中解析协议、计算 PID 或发送长报文。
- 控制周期内先采样四路编码器，再统一解算和输出，避免四轮采样时刻不一致。
- 逻辑层使用 `FL/FR/RL/RR`（左前、右前、左后、右后），板级层再映射到 A/B/C/D，避免机械安装变化污染运动学公式。
- 每个轮子独立配置“电机输出方向”和“编码器反馈方向”，不要靠在运动学公式里反复加负号修补。
- 停车、失联、使能关闭、欠压和初始化失败都走同一个总安全出口：四轮目标清零、PI 状态复位、所有 PWM 置为安全态。

## 5. 100 Hz 控制周期

每 10 ms 固定执行一次：

1. 原子化读取并清零 TIM2/3/4/5 的编码器增量。
2. 按实测的每轮每转计数、轮径和 10 ms 周期换算四轮线速度。
3. 检查 PD3 使能、蓝牙命令年龄、电池状态和软件急停。
4. 对 `vx/vy/wz` 做死区、最大值限制和加速度斜坡。
5. 麦轮逆解得到四轮目标速度。
6. 按四轮中最大绝对值做等比例归一化，保留运动方向，不逐轮硬裁剪破坏合成速度。
7. 四个速度 PI 分别计算 PWM，执行积分/输出限幅。
8. 一次性更新四组 H 桥输出。
9. 记录周期耗时和故障状态，供 10 Hz 遥测使用。

建议的逻辑公式先采用厂商工程的关系，最终符号由单轮测试确认：

```text
A = +vy + vx - wz * (half_length + half_width)
B = -vy + vx - wz * (half_length + half_width)
C = +vy + vx + wz * (half_length + half_width)
D = -vy + vx + wz * (half_length + half_width)
```

该公式不能在未确认 A/B/C/D 实际安装位置、滚子方向和电机接线前直接落地。最终代码应以 `FL/FR/RL/RR` 的标准公式表达，再通过配置表映射物理通道。

## 6. 蓝牙遥控协议建议

首版继续沿用 `diansai_test` 的 ASCII 行协议和 USART2 9600 baud，便于串口助手、手机蓝牙终端和后续自制 App 联调。

最小命令集建议为：

```text
DRV,<vx_percent>,<vy_percent>,<wz_percent>\n
PING\n
STOP\n
```

- 三个百分比均限制在 `-100..100`。
- 手机端应每 50~100 ms 重发一次 `DRV` 或 `PING`。
- MCU 超过 400 ms 未收到有效保活即停车，并要求新的有效 `DRV` 才恢复。
- `STOP` 立即清目标和 PI，不等待下一个超时。
- 数据格式错误、越界、半帧和串口错误都不得更新最后有效命令时间。
- 调试阶段可保留 10 Hz 文本遥测：四轮目标速度、实测速度、PWM、使能状态、命令年龄和电池电压。

不建议首版直接照搬厂商 App 的单字节八方向协议：它只能给离散方向，且原工程的通信失联停车逻辑未启用，不利于安全试车和连续三自由度控制。

## 7. 分阶段实施与验收

### 阶段 0：机械与电气参数确认

需要记录：

- MG513 的额定电压、减速比、霍尔每电机轴转脉冲数和编码方式。
- 麦轮直径、左右轮中心距、前后轮中心距。
- 四个麦轮的 X 型安装方向和 A/B/C/D 对应车身角点。
- 电池类型、串数、满电/最低安全电压和预计峰值电流。
- 蓝牙模块型号、供电电压、逻辑电平和默认波特率。

验收：形成唯一的硬件参数表；任何参数不明确时不进入满功率测试。

### 阶段 1：四路底层资源静态验证

- 在 `diansai_test.ioc` 中增加 TIM1 PWM、TIM4/TIM5 Encoder，保留 TIM2/3/9/10/11 和 USART2。
- 生成后检查 PE9/PE11/PE13/PE14、PB6/PB7、PA0/PA1 无复用冲突。
- 上电默认四路 PWM 为停止态，PD3 未使能时任何命令都不能驱动电机。

验收：编译无错误；未发送命令时四路输出均为停止态。

### 阶段 2：逐电机开环低功率台架

- 车轮悬空，一次只接/启用一个电机。
- 使用低 PWM 验证正转、反转、停止；记录每个通道的物理车轮位置。
- 同时观察对应编码器计数，确定每轮输出方向和反馈方向配置。
- 检查长时间停止、快速换向和使能开关动作。

验收：A/B/C/D 与车轮角点映射清楚；四轮“正目标 -> 正反馈”；失能立即停止。

### 阶段 3：逐轮速度闭环

- 用实测每转计数和轮径换算 m/s，不直接照抄厂商 `13 * 30 * 4` 或旧双轮标定值。
- 先只调 P，再逐步增加 I；从低速到中速，每次只调一个轮。
- 检查零目标复位、输出饱和、低速死区和堵转后的恢复。

建议验收指标：稳定中速下各轮稳态误差不超过目标的 10%，无持续振荡；零目标后不因积分残留再次启动。

### 阶段 4：四轮悬空运动学验证

依次发送纯 `+vx`、纯 `+vy`、纯 `+wz`，核对四轮方向组合；然后测试反向和斜向。若不正确，只修改物理映射和方向配置，不修改标准运动学公式。

验收：前进、后退、左移、右移、顺/逆时针旋转的轮向全部正确，切换命令无异常跳变。

### 阶段 5：低速落地麦轮试车

- 先限制最大指令和 PWM，验证前后、横移、旋转。
- 加入输入斜坡，降低启动、制动和换向冲击。
- 对四轮速度差做 PID 微调；观察机械装配、滚子方向和重心对横移的影响。
- 使用限流电源或电流表监测堵转/横移电流，因为板上没有 MCU 电流采样。

验收：所有基本动作可重复，失联 400 ms 内进入停车，STOP 和 PD3 失能立即生效，驱动和电机温升可接受。

### 阶段 6：蓝牙遥控闭环验收

- 手机端持续发送三轴指令和保活。
- 测试连接、断连、应用退到后台、乱码、半帧、快速连发和重新连接。
- 对遥测核对四轮目标、反馈和 PWM，确认通信不会拖慢 100 Hz 控制周期。

验收：蓝牙可连续控制三自由度；断连必停；重新连接不会自行恢复旧速度；控制循环无明显抖动或丢周期。

### 阶段 7：可选的航向保持

底盘基本动作稳定后，再加入 MPU6050 yaw-rate 闭环或相对航向保持。该功能不是首版麦轮驱动的前置条件，也不能替代四轮编码器速度闭环。

### 阶段 8：迁移 FreeRTOS

裸机版接口稳定后再迁移：

- `ChassisTask`：100 Hz，拥有编码器采样、运动学、PI 和 PWM 输出。
- `CommTask`：解析串口，向底盘提交完整命令快照。
- `TelemetryTask`：10 Hz，低优先级发送状态。
- 使用队列或双缓冲传递命令；ISR 仍只负责收字节/通知。
- 迁移前后使用同一组方向、失联、速度误差和周期抖动验收项，确保 RTOS 不改变底盘行为。

## 8. 开工前的关键决策

下一阶段开始写代码前，只需先确认以下五项：

1. 四个 MG513 的完整规格或铭牌照片，尤其是减速比和霍尔线数。
2. 麦轮直径、前后轮距、左右轮距及 X 型安装照片。
3. A/B/C/D 分别接哪个车轮；若尚未接线，可在阶段 2 现场建立映射。
4. 电池规格和蓝牙模块型号。
5. 手机端是先用通用蓝牙串口 App，还是直接制作专用遥控界面。

这些信息确认后，首个代码任务应当是“在现有 `diansai_test` 上增加 C/D 电机和 TIM4/TIM5 编码器的最小四轮台架版本”，仍不先加入麦轮运动学或 RTOS。
