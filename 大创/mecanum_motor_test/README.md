# Mecanum Motor Control

## Current firmware: SERVO AUTO R5 (2026-10-26)

R5 retains the R4 servo bus mapping, moved from USART2 to **USART3 at 1000000 baud, 8N1: PC10 TX, PC11 RX, common GND**. PD5/PD6 are no longer used by the servo driver. Disconnect any other module from PC10/PC11 for this test.

The active application temporarily runs only the ST3215 USER-key test and OLED diagnostics. Vehicle, motor PWM startup, encoder acquisition, IMU, PS2, battery acquisition and Bluetooth/host command tasks are not started or processed. Their source files and CubeMX peripheral configuration are retained for later restoration; generated peripheral initialization alone does not start those application functions.

OLED first line must read `SERVO AUTO R5`. Other lines show raw `KEY` (1 = pressed), debounced `PRESS` count, operating state (`AUTO`, `PAUSE`, `FAULT`), last `CMD` (`+`, `-`, `R`, `S`), successful command `OK` count, uptime `UP` in seconds, and `ERR` count. Counters wrap only on screen. The version stays visible even when the servo is disconnected. A changing uptime confirms that the application is running. Key capture remains active during communication faults so pause/resume presses are still recorded.

On power-up, R5 automatically moves +341 counts (29.9707 degrees) then -341 counts repeatedly. USER press immediately toggles pause/resume after 10 ms debounce; no double-click or hold gesture remains. A held key toggles once. Each leg is issued once, waits at least 1200 ms, checks the moving/status feedback every 100 ms, then dwells for 250 ms at the endpoint. A leg still moving at 3000 ms faults. Pause turns torque off; resume clears the interrupted goal and starts a new forward leg from the current position. Communication errors or motion timeout stop and pause the test; connection recovery stays paused until a new USER press. SERVO_R5_VALIDATION.md records the build, HEX hash and COM7 readback outcome. Earlier chassis sections below describe the retained source, not the active R5 runtime.

Bare-metal STM32F407VET6 four-wheel mecanum chassis firmware generated by STM32CubeMX 6.17.0 for Keil MDK-ARM V5.

## Hardware mapping

| Motor | Position | PWM inputs | Encoder |
| --- | --- | --- | --- |
| A | Right rear | PB8/TIM10_CH1, PB9/TIM11_CH1 | PA15/PB3, TIM2 |
| B | Left rear | PE5/PE6, TIM9_CH1/CH2 | PB4/PB5, TIM3 |
| C | Right front | PE9/PE11, TIM1_CH1/CH2 | PB6/PB7, TIM4 |
| D | Left front | PE13/PE14, TIM1_CH3/CH4 | PA0/PA1, TIM5 |

PD3 is the active-high motor enable input. PB0/ADC1_IN8 measures VIN through a 100k/10k divider.

The controller board's dedicated PS2 connector uses PE15/DI, PE12/DO, PE10/CS, and PE8/CLK. Supply the receiver from the connector's 3.3 V and GND pins.

## Control

- Position-form PID at a 20 ms bare-metal control period.
- Per-wheel encoder calibration: A 1560.3, B 1557.4, C 1562.6, D 1557.6 count/rev.
- Default gains: Kp 1.0, Ki 0.2, Kd 0.0.
- Default target: 30 RPM; output limit: 60%; integral limit: 30%.
- Four independent controller states with shared tunable gains.
- 300 ms motion-command watchdog.

## PS2 control

- Turn on the handset and wait for the receiver to pair.
- Keep both sticks centered and press `START` to arm motion.
- Left stick Y controls forward/backward motion.
- Left stick X controls left/right mecanum translation.
- Right stick X controls left/right rotation.
- Press `SELECT` to stop and disarm. A lost/invalid controller frame also stops and disarms immediately.
- OLED PS2 status: `P:-` disconnected, `P:S` connected/standby, `P:A` armed.

Bluetooth and host-computer command reception are intentionally not initialized in the active application flow. Their source files remain in the project for later reuse.

## ST3215 USER-key test (SERVO_R2, 2026-10-26)

- Replace the Bluetooth module with the TTL bus-servo adapter on USART2: PD5/TX and PD6/RX, common ground. USART2 is now 1000000 baud, 8N1. The adapter handles the half-duplex servo bus. Servo ID is 1 (factory default); do not share that ID with another servo.
- USER is PE0, active low. Single click: +30 degrees; double click within 300 ms: -30 degrees. Single click is dispatched after the double-click window. Hold for 500 ms: continuous positive rotation; release: torque off (coasts rather than holding position). The next click uses relative step mode.
- Resolution is 4096 counts/revolution, so each click requests 341 counts (29.9707 degrees). Relative step mode avoids crossing-zero direction ambiguity. Speed is 500 counts/s (about 44 degrees/s), acceleration 50. Positive direction follows the servo's existing phase configuration.
- Debounce is 10 ms with independent 1 ms SysTick sampling. A bounded interrupt-to-main event queue retains short presses while PS2 reconfiguration or foreground I/O blocks the main loop. SysTick performs no UART operations. Double-click timing uses the second press, so holding the second click longer does not discard the first click. Single-click execution still waits 300 ms to distinguish it from a double click. A key held at boot must be released before use. OLED `S:S` is ready/stopped (or executing a step), `S:R` continuous rotation, `S:E` no valid response/fault. Servo initialization leaves torque off; no boot movement is requested.
- Mode, zero angle limits required by step mode, and speed-unit bit are changed only while EEPROM is locked. ID, baud rate, center calibration and persistent configuration are not rewritten. Failed communication inhibits new motion, retries torque-off/init every 100 ms and requires a fresh press after recovery. During continuous rotation, status is checked every 100 ms; loss of the physical signal prevents delivery of a stop until communication returns.
- Chassis/PS2 behavior remains available. The Bluetooth command receiver remains inactive.
